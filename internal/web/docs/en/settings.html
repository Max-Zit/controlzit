Server settings and updates

Administrators find the server's settings under Settings: network and ports, the certificate, time zone, updates of the server and the agents, and the diagnostics for support.

Network and access

Under Settings → Network and access:

  • Console — listen address and port (default :8443) and the allowed networks: one IP address or network per line (CIDR). Connections from other addresses are closed before TLS; the server itself (127.0.0.1) is always allowed. Saving refuses a list that would lock out your own address.
  • Agent endpoint — listen address and port (default :8444, must differ from the console), the networks agents may come from (empty = all) and the public agent address put into installers and enrollment codes.
  • New ports take effect after Restart now (restarts the RMMZit service; agents reconnect by themselves).

If you lock yourself out, run rmmzit-server --reset-allowlist on the server (appliance: setup menu, item 5).

Network of the server (appliance)

On the RMMZit appliance the server's own network is set here too: DHCP or a fixed address with network size (e.g. 192.168.1.20/24), gateway, one to three DNS servers and the server name. If the gateway does not answer with the new settings, the previous ones come back by themselves after 30 seconds. On other installations the operating system manages the network.

Time zone

Schedules (updates, scripts, reports) and the times in the console use the server's time zone. Choose it from the list and click Set; the console restarts and is back in a few seconds. Without the root helper (see below), set it on the server: timedatectl set-timezone Europe/Berlin.

Certificate (HTTPS)

Under Settings → Certificate choose the certificate browsers see when they open the console. Agents use their own port and certificate, so changing it never disconnects them.

  • The console's own certificate (self-signed) — works at once; browsers warn about it.
  • Let's Encrypt — a free certificate, renewed automatically 30 days before it expires. Enter the console's public DNS name and an email address, and choose the check:
    • port 80 — the name points to this server and port 80 is reachable from the internet; the server answers on port 80 and redirects browsers to HTTPS;
    • Cloudflare DNS — for servers that are not reachable from the internet; needs a Cloudflare API token with Zone:DNS:Edit for the zone.
  • Upload a certificate from your certificate authority or company CA: the certificate (PEM, with the intermediate certificates) and the private key. The key is stored only on this server.

Updates of the server

Settings → RMMZit updates shows the running version and the newest release. Install updates the server: only releases signed with the RMMZit release key are installed; before installing, the server backs up its database and program, and if the new version does not start it goes back to the old one by itself. The console is away for a minute or two. Optionally new versions are installed automatically in a chosen hour.

Update channel: Official releases (the default) or Testing, which offers release candidates before they become official, for a test console. Keep production consoles on official releases.

Updates, the time zone and the network need the root helper that comes with the Linux packages and the appliance. Without it (e.g. the plain program), update with install.sh or the package of the release.

Diagnostics

Settings → Diagnostics shows where RMMZit writes its logs, the newest lines of the server log (filter by level or text), the root helper's log and the versions. Download diagnostics (ZIP) creates a file for support with the logs, the versions and settings summary, the devices, the alerts and the audit log. Passwords, tokens, enrollment codes and keys are removed from everything shown and from the file; scripts and their output are not included.

Custom fields

Under Settings → Custom fields administrators add their own fields for devices and customers — text, number or date — for example an asset number, the end of the warranty or a contract. Technicians fill them in on the device and customer pages; the API returns the device fields with each device and sets them with PUT /api/v1/devices/{id}/fields.

Console backup

Settings → Console backup backs up the console every day at the chosen hour, or at once with Back up now. A backup holds the database, the secret key of the stored passwords, the certificates and keys the agents trust, and the software library. The newest backups (as many as you choose) stay in the folder backups of the data directory and can be downloaded from the page.

With a passphrase the files are encrypted (AES-256-GCM); keep the passphrase elsewhere, because without it a backup cannot be restored. A copy of each backup can go to an SFTP folder on another server (password or private key). The first test of the connection shows the server's host key to trust; copies go only to a server with that key. When a backup or its copy fails, the alert email recipients get an email.

A restore runs with the server stopped: on the appliance in the setup menu (Restore a backup), with the Linux packages:

sudo systemctl stop rmmzit-server
sudo -u rmmzit sh -c 'set -a; . /etc/rmmzit/server.env; rmmzit-server -data-dir /var/lib/rmmzit -restore /path/rmmzit-backup-….czb'
sudo systemctl start rmmzit-server

The passphrase of an encrypted backup is read from RMMZIT_BACKUP_PASSPHRASE or from a file given with -restore-passphrase-file. The database is restored in one step (nothing changes if that fails); a newer RMMZit updates the restored database when it starts. A new server restored from a backup keeps all agents, because they trust the same certificate.

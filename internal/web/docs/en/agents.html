Installing agents

The agent is a small service on every managed computer. It connects outbound to the agent port of the server, reports inventory and metrics and runs the signed commands of the console.

Before you start

  • Agents must reach the server on the agent port (TCP 8444 by default). For computers outside your network, open this port on the firewall and set the public agent address under Settings → Network and access (for example https://rmm.example.com:8444). The console port stays closed.
  • If you opened the console on the server itself (localhost) and no public agent address is set, the site page warns you: agents would try to connect to the server's own loopback address.

Enrollment codes

Agents join a site of a customer with an enrollment code. Open the site under Customers and click Create enrollment code. You choose how long it is valid (1–365 days) and how many computers may use it. The code (RZ1-…) contains the server address and the fingerprint of the server certificate, so the installer needs nothing else. It is shown only once; revoke it when it is no longer needed.

Windows

Download the MSI on the site page (Download the agent (MSI, 64-bit)) and either double-click it and paste the code, or install it silently, for example with Group Policy, Intune or a script:

msiexec /i rmmzit-agent-x64.msi /qn ENROLLCODE="RZ1-…"

The agent runs as the Windows service RMMZit Agent. A small icon next to the clock shows whether it is connected (green) and opens a window with the server and who manages the computer.

The icon, its window and the restart question speak the display language of the user's Windows (one of the 14 languages of the console, otherwise English).

Without the MSI (PowerShell as administrator):

.\rmmzit-agent.exe enroll --code "RZ1-…"
.\rmmzit-agent.exe install

Linux

Download the Linux agent on the site page (x86-64, or ARM64 for Raspberry Pi and ARM servers), copy it to the machine and run as root:

chmod +x rmmzit-agent-linux-amd64
sudo ./rmmzit-agent-linux-amd64 install --code "RZ1-…"

It copies itself to /usr/local/bin/rmmzit-agent, enrolls and starts the systemd service rmmzit-agent.

Agent updates

The server carries the agent installers of its own version. Under Settings → Agent updates you see which agents are outdated, update them all at once, or let outdated agents update by themselves when they connect. A single agent is updated on its device page. The agent downloads the installer over its own encrypted connection and installs it only if it matches the SHA-256 in the signed update command. You can also upload another installer there (an MSI or a Linux agent).

Windows Update on managed computers

The agent switches off the automatic installation of Windows Update by policy, so that updates arrive only from RMMZit, by hand or on your schedule (see Windows updates). The previous settings are saved and come back when the agent is removed.

Removing an agent

Delete the device on its page (Remove device). If it is online, the agent uninstalls itself within seconds and Windows Update gets its own settings back. An offline computer can no longer connect; uninstall the agent there by hand (Windows: Apps → RMMZit Agent → Uninstall; Linux: sudo rmmzit-agent uninstall).

Many computers: Group Policy and Intune

Create an enrollment code with enough uses for all computers; the site page then shows, filled in with that code:

  • Group Policy: a PowerShell startup script. Put the MSI on a share the computer accounts (Domain Computers) may read, enter its path, copy the script and add it under Computer Configuration → Policies → Windows Settings → Scripts → Startup → PowerShell Scripts. Computers that have the agent (service RMMZitAgent) skip it; the installation log is %windir%\Temp\rmmzit-agent-install.log.
  • Microsoft Intune: add the agent as a Windows app (Win32): pack the MSI with Microsoft's IntuneWinAppUtil and use the install and uninstall commands, install behavior System and the detection rule (file C:\Program Files\RMMZit Agent\rmmzit-agent.exe) shown on the site page. Do not add it as a line-of-business MSI: the agent updates itself, and Intune would install the old version again.

Installing the server

Choose one of five ways. The ready-made VM image is the fastest; the install script suits an existing Linux server, Docker an existing Docker host.

WayBest forNeeds
1. VM image (OVA, qcow2, VHDX)import, start, sign in, in a few minutesVMware, Proxmox / KVM or Hyper-V
2. Appliance ISOa new VM or a physical server, unattendedinternet access during the installation
3. Install scriptan existing Debian, Ubuntu, AlmaLinux or Rocky Linux serverroot and internet access
4. Packages by handyour own PostgreSQL, configuration management, offline serversthe deb or rpm package of a release
5. Docker (container image)an existing Docker host, NAS or home labDocker with the Compose plugin; internet access to pull the image

All files are on the release page. Give the server 2 vCPU, 2–4 GB RAM and a 16 GB or larger disk.

1. VM image

  1. Import the image:
    • VMware ESXi / Workstation, VirtualBox: deploy rmmzit-appliance.ova (Create / Register VM → Deploy a virtual machine from an OVF or OVA file).
    • Proxmox VE: create a VM without a disk (2 vCPU, 2–4 GB RAM, VirtIO network), copy rmmzit-appliance.qcow2 to the node and run qm importdisk <vmid> rmmzit-appliance.qcow2 local-lvm; attach the disk as SCSI and make it the boot disk.
    • Hyper-V: unzip rmmzit-appliance-vhdx.zip and create a generation 1 VM with the VHDX as its disk.
  2. Start the VM. The disk grows to the size of the virtual disk by itself. The screen of the VM shows the address of the console and the setup token.
  3. Open https://<address>:8443. The browser warns once about the self-signed certificate (replace it later under Settings → Certificate). Enter the setup token and create the first administrator.

The appliance gets its address by DHCP. To set a fixed address, the server name or the time zone, sign in on the VM's own screen as rzadmin (first password rmmzit, which must be changed): a setup menu opens. The time zone and the network can also be changed later in the console.

2. Appliance ISO

  1. Boot a VM or a server from rmmzit-appliance.iso. After 5 seconds the installation starts by itself: it erases the first disk, installs Debian, PostgreSQL and RMMZit and needs internet access (10–20 minutes).
  2. After the restart the screen shows the console address and the setup token, as with the VM image.

3. Install script

On an existing Linux server, as root:

curl -fsSL https://github.com/Max-Zit/rmmzit/releases/latest/download/install.sh | sudo sh

The script installs PostgreSQL, downloads the newest release, checks its signature, creates a database with a random password and starts the service. Options (after sh -s --): --version X, --db postgres://… for an existing database, --no-auto-updates to leave the automatic security updates of the operating system off. Running it again updates RMMZit and keeps the data.

4. Packages by hand

sudo apt install ./rmmzit-server_X_amd64.deb      # Debian, Ubuntu
sudo dnf install ./rmmzit-server-X-1.x86_64.rpm     # AlmaLinux, Rocky Linux

Then put the database address into /etc/rmmzit/server.env (RMMZIT_DB=postgres://…) and start the service with systemctl enable --now rmmzit-server.

5. Docker

The server is also a container image, ghcr.io/max-zit/rmmzit, built from the same signed server package as the other ways; it runs with PostgreSQL through Docker Compose. Download docker-compose.yml and .env.example into a folder, copy .env.example to .env, set a database password (letters and digits) and the time zone, then:

docker compose up -d
docker compose exec rmmzit rmmzit-server -setup-token

Open https://<host>:8443 and enter the setup token. Port 8444 is the agent endpoint; open it where agents connect from. The image tag in .env decides what runs: latest for official releases, testing for release candidates.

Update with docker compose pull && docker compose up -d. Before a new version changes the database, the server writes a backup to Settings → Console backup. To go back, set the previous version as the image tag and restore that file: docker compose stop rmmzit, docker compose run --rm rmmzit -restore /var/lib/rmmzit/backups/FILE, docker compose up -d. In a container the network and the time zone belong to the Docker host, not to the console.

First sign-in

  • The setup token is in /var/lib/rmmzit/setup-token.txt and in the server log (journalctl -u rmmzit-server). It works once.
  • Every account needs an authenticator app (TOTP) and gets 10 recovery codes. Keep them safe.
  • The console accepts connections only from private networks by default. If you lock yourself out, run rmmzit-server --reset-allowlist on the server (on the appliance: setup menu, item 5).

Where things are

PathWhat
/etc/rmmzit/server.envconfiguration: database, ports, update source (readable by root and the service only)
/var/lib/rmmzitdata directory: certificates, secret key, agent installers (downloads), logs
/var/lib/rmmzit/logs/server.logserver log; also in journalctl -u rmmzit-server
/var/log/rmmzit-helperlog of the root helper (updates, time zone, network)

Back up the database together with /var/lib/rmmzit: the secret key there decrypts the stored passwords and the certificates identify the server to its agents.

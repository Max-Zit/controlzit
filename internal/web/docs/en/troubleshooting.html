Troubleshooting and FAQ

The most common questions and what to check first. For a support request, download the diagnostics under Settings → Diagnostics.

I cannot reach the console

  • Your address may not be in the allowed networks: the connection is closed before TLS, so the browser shows a connection error. Run rmmzit-server --reset-allowlist on the server (appliance: setup menu, item 5) to allow all private networks again.
  • After changing the port, open the console on the new port.
  • Check the service on the server: systemctl status rmmzit-server and journalctl -u rmmzit-server.

Sign-in problems

  • The code is wrong — the phone's time must be correct (automatic time).
  • Lost phone — sign in with a recovery code; another administrator can reset two-factor sign-in.
  • Too many failed attempts — the address is blocked for a while; an administrator can Unblock it under Settings → Sign-in and security. Sign-ins from the server itself are never blocked.
  • LDAP / single sign-on — use Test on the LDAP page; check the groups the provider sends. The server log has the details.

An agent does not connect

  • Can the computer reach the agent port? On Windows: Test-NetConnection rmm.example.com -Port 8444.
  • Is the public agent address right? Codes created while the console was opened on localhost point the agent at the wrong server; set the address and create a new code.
  • Is the code still valid and not used up?
  • Agent logs: Windows C:\ProgramData\RMMZit Agent\agent.log, Linux /var/lib/rmmzit-agent/agent.log and journalctl -u rmmzit-agent; for a connected device, open them from the console under Files. On Windows, the icon next to the clock shows the connection state.

Remote desktop shows nothing

  • Linux with Wayland cannot be shown: sign in with an X11 (Xorg) session or use the terminal.
  • Linux without a desktop: use the terminal.
  • Copying files through the clipboard needs a signed-in user on the Windows computer.

Windows updates are not installed

  • Check the automatic installation in the device's Policy tab: which policy sets Windows Update, the days, the hour and the mode. Devices must be online in that hour.
  • The device's Updates tab shows the last search and its error, if any.

Alert emails do not arrive

Use Send a test email under Settings → Monitoring and alerts; the message shows the server's answer. A password is sent only over STARTTLS or TLS.

FAQ

Does RMMZit need a cloud service?

No. Everything runs on your server; nothing is sent to MaxZit. The server only checks GitHub for new releases.

How do I back up RMMZit?

Under Settings → Console backup the server backs up its database, secret key and certificates every day, optionally encrypted and copied to an SFTP server. Keep a copy outside the server: without the secret key, stored passwords cannot be decrypted and agents would not trust a new server.

Can I move the server to a new machine?

Yes: install RMMZit on the new machine and restore a console backup there (rmmzit-server -restore FILE, on the appliance item 7 of the setup menu). Keep the same address, or update the public agent address and point the old name to the new machine; agents keep working because the backup holds the server's certificates.

Is there a macOS agent?

Not yet. Windows and Linux (x86-64, ARM64) are supported.

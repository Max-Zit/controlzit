Getting started

RMMZit is a self-hosted remote monitoring and management (RMM) tool. From one web console on your own server you watch and manage the Windows and Linux computers of your customers: inventory, monitoring and alerts, remote desktop, terminal, files, scripts, Windows updates, software and reports.

What RMMZit does

AreaWhat you get
InventoryHardware, operating system, disks, network, security state (antivirus, firewall, BitLocker) and installed software of every device. Devices
Monitoring and alertsCPU, memory, disk space, offline devices, stopped services, Defender and firewall, disk health, network checks, Windows event logs and processes; history with a disk-full forecast; alerts by email, Slack, Microsoft Teams or webhook. Monitoring
Remote accessRemote desktop in the browser (Windows, Linux with X11) with clipboard and file copy, a terminal (PowerShell on Windows, root shell on Linux), a file manager, processes, services, registry editor and scheduled tasks on Windows, restart and shutdown. Remote access
ScriptsPowerShell, cmd, bash or sh on one device, on many devices at once or on a schedule, from a script library. Scripts
Updates and softwareMissing Windows updates and Linux packages, installation by hand or on a schedule, programs through winget or Chocolatey, your own MSI/EXE library, vulnerabilities of installed programs. Updates
PoliciesSettings per customer, site or device: Windows Update, required and blocked software, program updates, restarts, maintenance windows, alert rules, monitors, automations and BitLocker. Policies
ReportsA report per customer (devices, updates, alerts, work of technicians), printable or sent by email every week or month. Reports

How it works

  • The server runs on a Linux machine (usually a small VM) with PostgreSQL. It has two ports: the console (web interface and API, TCP 8443) and the agent endpoint (TCP 8444).
  • Agents run as a service on every managed computer. They connect outbound to the agent port; the computers need no open ports. An agent trusts the server by the fingerprint of its certificate, which it pins when it enrolls.
  • Every command to an agent is signed by the server and checked by the agent, and every action is written to the tamper-evident audit log.

The console controls every managed computer. Keep it reachable only from your own networks (the default) and open only the agent port where agents need it. See Security.

First steps

  1. Install the server — import the ready-made VM image, boot the appliance ISO or run the install script on a Linux server. See Installing the server.
  2. Create the first administrator with the setup token shown on the server, and set up two-factor sign-in with an authenticator app.
  3. Check the agent address under Settings → Network and access: agents must reach the server by the public agent address or the console's host name.
  4. Add a customer and a site under Customers, then create an enrollment code on the site.
  5. Install the agent on the computers of that site with the code. See Installing agents.
  6. Set up alerts and automatic Windows updates in the customer's policy Default under Policies, and the alert emails under Settings → Monitoring and alerts.
  7. Add your technicians under Users, or connect Active Directory / LDAP or single sign-on. See Users, roles and sign-in.

Requirements

  • Server: 2 vCPU, 2–4 GB RAM, 16 GB disk; Debian 12+, Ubuntu 22.04+, AlmaLinux or Rocky Linux 9+ (or the ready-made appliance).
  • Windows agents: Windows 10 / 11, Windows Server 2016 and newer, 64-bit.
  • Linux agents: distributions with systemd, x86-64 or ARM64 (Raspberry Pi and ARM servers). Updates through apt or dnf.
  • Browser: a current Chrome, Edge, Firefox or Safari.

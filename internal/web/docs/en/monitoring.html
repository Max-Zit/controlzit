Monitoring, alerts and notifications

The server checks every device once a minute. An alert opens while its condition holds and closes by itself when it is gone; you are told by email, in a chat channel or through a webhook.

Alert rules

Set the rules in the policies of the customers, sites and devices (every customer has its policy Default). Alert emails, the email server and chat channels are under Settings → Monitoring and alerts.

Alerts are a Warning or Critical (critical: offline devices, stopped services, Defender off, and disks with less than 1 GB free or 98 % used). Alerts lists the open ones (and, if you want, the resolved ones); a technician can acknowledge an alert so others see that someone is on it. The number of open alerts is shown in the menu.

Network checks

The Network checks part of a policy lists addresses that every device of the policy checks every minute from its own network: ping (a router, a printer, a server), a TCP port (for example a database on 1433) or a web address, which must answer without an HTTP error and with a valid certificate. An alert opens when a check fails longer than its minutes, and 14 days before the certificate of a web address expires. The device's overview shows each check with its response time.

Disk health

Once an hour the devices report the health of their physical disks: on Windows what the disks report to Windows (SMART: health, temperature, wear of SSDs, uncorrected errors) and the Storage Spaces disks; on Linux SMART through smartctl (package smartmontools) and the md software RAID arrays. A disk that reports a problem and a degraded RAID array open an alert, unless the policy's alert rules switch this off. Disks behind a hardware RAID controller are not visible to the system and are not covered. The device's overview shows the disks.

Alert emails

  1. Enter the email server (SMTP): host, port, connection security (STARTTLS or TLS; a password is never sent over an unencrypted connection), user, password and sender. The password is stored encrypted.
  2. Add the recipients, one address per line, and choose whether an email also goes out when an alert is resolved.
  3. Click Send a test email.

Slack, Microsoft Teams and webhooks

Under Chat and webhooks add up to 20 channels:

  • Slack — an incoming webhook URL of the channel.
  • Microsoft Teams — a channel workflow When a Teams webhook request is received, and its URL.
  • Webhook — any HTTPS URL that accepts a JSON POST (ticket system, automation). With a secret, every request carries X-RMMZit-Signature: sha256=<HMAC of the body>, so the receiver can check it came from your server.

For each channel choose all alerts or only critical ones, and whether resolved alerts are sent too. Send test sends a test message. Channel addresses are stored encrypted.

Live values

The device page shows the current CPU load, memory and disks, and the automatic services that are not running.

History and disk forecast

The History tab of a device draws its CPU load, memory, network traffic (agents 0.11 and newer) and the used space of each disk over 24 hours, 7, 30 or 90 days. The minute values are kept 7 days, hourly summaries 90 days.

From the hourly disk space the server computes when each disk will be full if it keeps growing as in the last 14 days. A disk that will be full within 90 days is shown on the device page; the alert rule Disk full soon opens an alert within the days set in the policy (14 for new policies; critical within 3 days).

Monitors: events and processes

The Monitors part of a policy watches the Windows event logs and programs that must run. The devices of the policy are asked every 5 minutes (agents 0.12 and newer).

  • Event rules: a log (System, Application, Security or Setup), optionally event IDs, a source and a level, and how many matching events within how many minutes open an alert (warning or critical). Examples: Security 4625 (failed sign-ins) 5 times within 10 minutes; System 41 (unexpected restart); System 7031 and 7034 (a service ended unexpectedly). Events of the Security log have no level: keep the level at any.
  • Processes that must run: a program name such as sqlservr.exe (Windows) or nginx (Linux); an alert opens while it is not running.

The device page shows each rule with its last result. The alert closes by itself when the condition is gone.

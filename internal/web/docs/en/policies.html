Policies

A policy sets Windows Update, required software, alert rules and automations for the customers, sites or devices it is assigned to, so that every computer of an office or a customer is managed the same way.

Parts of a policy

  • Windows Update — what is installed automatically, on which days and at which hour, and whether the computer restarts when an update needs it.
  • Required software — programs every Windows device of the policy must have; missing ones are installed by the server.
  • Alert rules — the thresholds for CPU, memory, disks, offline devices and pending restarts, Defender and the firewall, and the services that must run.
  • Automations — library scripts that run on the policy's devices on set days and at a set time.
  • BitLocker — encryption of the system drive with the recovery key kept on the server.
  • Network checks — addresses the devices check every minute from their own network (ping, a TCP port, a web address).
  • Program updates — updating the installed programs that winget or Chocolatey know, on set days or in the maintenance window.
  • Maintenance windows — when the devices may be busy: installations, forced restarts and, if you want, no new alerts.

Each part is switched on or off in the policy. A part that is off is not set by this policy: it comes from a less specific policy or from the built-in defaults (no automatic updates, standard alert rules).

Assigning a policy

Create policies under Policies. On a policy's page, Assign to gives it to a customer, a site or a single device; the Policy tab of a device sets the device's own policy. A customer, site or device has one policy; assigning another replaces it.

For each part, the most specific assignment that sets it applies: the device's policy, then the site's, then the customer's, then the built-in defaults. Example: the customer's policy sets Windows Update and required software, a site's policy sets only stricter alert rules — the devices of that site get the customer's updates and software and the site's alert rules.

A policy belongs either to one customer or to the whole server, chosen when it is created. Technicians create and change the policies of their customers and assign them to those customers, their sites and devices; administrators manage all policies, and only they create server-wide policies and set the BitLocker part. A customer's policy can never be assigned outside its customer.

Every new customer gets its own policy Default, assigned to it, with the built-in Windows Update and alert settings; change it, or give sites and devices their own policies. On the upgrade to version 0.6.3, every existing customer without a policy got a Default policy with the server's former Windows Update and alert settings, which are no longer under Settings.

Required software

Each required program has a source — the software library, winget or Chocolatey — and a text that its name in the Windows list of installed programs contains (for example 7-Zip). Every few minutes the server compares the required programs with the inventory of each online Windows device; a missing program is installed as a task you see under the device's Activity. After an installation the device sends a new inventory. If the program is still missing, the server tries again after 6 hours. Nothing is installed before a device has sent its first inventory.

Alert rules

The thresholds of a policy apply to its devices. Alert emails and chat channels are set for the whole server under Monitoring and alerts.

Automations

An automation runs a script of the script library on the chosen days and time (server time) as one job for all devices whose automations come from this policy. Offline devices run it when they connect, within 24 hours; the results are on the job's page and under each device's Activity.

BitLocker and recovery keys

The server keeps the BitLocker recovery keys of its Windows devices: once a day it reads them from every device with BitLocker on, and Read the recovery keys now on the device's BitLocker page (linked from the BitLocker line of the device overview) reads them at once. The keys are stored encrypted with the server's secret key. Only administrators can show a key, after entering their password; every key shown and every wrong password is recorded in the audit log.

A policy with Require BitLocker on the system drive switches it on for Windows devices whose system drive is not encrypted. The agent first checks the TPM and adds a recovery key; the server stores the key, and only then does the encryption start (TPM protector, XTS-AES 256, used space only), in the background while the computer is in use. Devices without a ready TPM or with a Windows edition without BitLocker (Home) show the reason under Activity, and the server tries again after 6 hours. Administrators can also switch it on for one device from its BitLocker page.

Program updates

The Program updates part updates the installed programs that have a newer version: those winget knows and, if you choose, those installed with Chocolatey. It runs once on each chosen day at the chosen hour, or in the maintenance window. Programs on the Do not update list (package IDs or parts of names) are left alone. With an update ring delay, a new version waits that many days after the server first saw it. Each run shows under the device's Activity.

Maintenance windows

A maintenance window is a weekly time span, for example Saturday from 22:00 for 4 hours (server time). Windows updates and program updates set to In the maintenance window run then, and a restart past its deadline waits for the next window. With No new alerts during a maintenance window, the devices open no new alerts while a window is open; alerts already open stay as they are.

What applies to a device

The Policy tab of a device shows, for each part, which policy sets it (and whether it is assigned to the device, its site or its customer) or that the built-in defaults apply, the state of every required program (installed, missing, when an installation was started), the Windows Update and alert settings that apply and the automations.

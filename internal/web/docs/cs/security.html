Bezpečnost

RMM server může ovládat každý počítač, který spravuje. RMMZit je postaven tak, aby útočník, který se dostane ke konzoli, do sítě nebo dokonce na server, získal co nejméně.

Jak vás RMMZit chrání

  • Dva porty. Konzole a koncový bod agentů naslouchají na oddělených portech. Konzole přijímá spojení jen z povolených sítí, ověřená před TLS; port agentů může být veřejný, aniž by odhalil konzoli.
  • Odchozí agenti. Agenti se připojují k serveru; spravované počítače nepotřebují otevřené porty. Agenti si připnou certifikát serveru podle otisku, takže falešný server je nepřevezme.
  • Podepsané příkazy. Každý příkaz agentovi je podepsán klíčem pro příkazy serveru a agent jej ověří; aktualizace agentů musí odpovídat SHA-256 v podepsaném příkazu.
  • Silné přihlášení. Dvoufázové přihlášení pro každý místní i adresářový účet, hesla argon2id, krátké relace, odhlášení po nečinnosti, rostoucí blokace neúspěšných přihlášení.
  • Ochrany prohlížeče. Kontroly CSRF při každé změně, přísná Content Security Policy bez vložených skriptů, cookies relace __Host-.
  • Nejmenší oprávnění. Role a přístup podle zákazníka; konzole běží jako neprivilegovaný uživatel a několik root akcí (aktualizace, síť, časové pásmo) jde přes samostatného root pomocníka, který přijímá jen pevné, ověřené požadavky.
  • Audit. Auditní protokol zřetězený haši pro každou změnu a každou vzdálenou akci.
  • Podepsaná vydání. Server, agenti a install.sh instalují jen vydání podepsaná klíčem vydání RMMZit.
  • Tajemství. Uložená hesla (e-mail, LDAP, kanály, Cloudflare) se šifrují tajným klíčem serveru; diagnostika tajemství odstraňuje.

Doporučené postupy

  1. Konzoli zpřístupněte jen ze svých správcovských sítí; pro přístup zvenku použijte VPN (například WireGuard) místo otevření portu konzole.
  2. Port agentů otevřete jen tam, kde jsou agenti, a nastavte sítě agentů, pokud všichni přicházejí ze známých adres.
  3. Používejte certifikát, kterému prohlížeče důvěřují (Let's Encrypt nebo vaše CA), aby si uživatelé nezvykli přeskakovat varování.
  4. Dejte každé osobě vlastní účet s nejmenší rolí a jen potřebnými zákazníky; vypínejte účty lidí, kteří odcházejí.
  5. Ponechte si jednoho místního správce pro nouzové situace se záložními kódy uloženými offline.
  6. Instalujte aktualizace RMMZit včas (nebo zapněte automatické) a udržujte operační systém serveru aktuální; appliance instaluje bezpečnostní aktualizace Debianu sama.
  7. Pravidelně zálohujte databázi a /var/lib/rmmzit a zálohu uchovávejte mimo server.
  8. Občas projděte auditní protokol a ponechte zapnuté upozornění na vzdálené obrazovce, aby uživatelé věděli, kdy je někdo připojen.

Nahlášení zranitelnosti

Bezpečnostní problémy hlaste soukromě přes GitHub → Security → Report a vulnerability, ne ve veřejném issue.

Resolução de problemas e perguntas frequentes

As perguntas mais comuns e o que verificar primeiro. Para um pedido de suporte, transfira o diagnóstico em Definições → Diagnóstico.

Não consigo aceder à consola

  • O seu endereço pode não estar nas redes permitidas: a ligação é fechada antes do TLS, por isso o navegador mostra um erro de ligação. Execute rmmzit-server --reset-allowlist no servidor (appliance: menu de configuração, opção 5) para voltar a permitir todas as redes privadas.
  • Depois de mudar a porta, abra a consola na nova porta.
  • Verifique o serviço no servidor: systemctl status rmmzit-server e journalctl -u rmmzit-server.

Problemas de início de sessão

  • O código está errado — a hora do telemóvel tem de estar certa (hora automática).
  • Telemóvel perdido — inicie sessão com um código de recuperação; outro administrador pode repor o início de sessão em dois passos.
  • Demasiadas tentativas falhadas — o endereço fica bloqueado durante algum tempo; um administrador pode desbloqueá-lo em Definições → Início de sessão e segurança. Os inícios de sessão a partir do próprio servidor nunca são bloqueados.
  • LDAP / início de sessão único — use Testar na página do LDAP; verifique os grupos que o fornecedor envia. O registo do servidor tem os detalhes.

Um agente não se liga

  • O computador chega à porta dos agentes? No Windows: Test-NetConnection rmm.example.com -Port 8444.
  • O endereço público dos agentes está correto? Os códigos criados com a consola aberta em localhost enviam o agente para o servidor errado; defina o endereço e crie um novo código.
  • O código ainda é válido e não se esgotou?
  • Registos do agente: Windows C:\ProgramData\RMMZit Agent\agent.log, Linux /var/lib/rmmzit-agent/agent.log e journalctl -u rmmzit-agent; para um dispositivo ligado, abra-os a partir da consola em Ficheiros. No Windows, o ícone junto ao relógio mostra o estado da ligação.

O ambiente de trabalho remoto não mostra nada

  • Linux com Wayland não pode ser mostrado: inicie uma sessão X11 (Xorg) ou use o terminal.
  • Linux sem ambiente gráfico: use o terminal.
  • Copiar ficheiros pela área de transferência precisa de um utilizador com sessão iniciada no computador Windows.

As atualizações do Windows não são instaladas

  • Verifique a instalação automática na aba Política do dispositivo: qual política define o Windows Update, os dias, a hora e o modo. Os dispositivos precisam estar online nessa hora.
  • O separador Atualizações do dispositivo mostra a última pesquisa e o seu erro, se existir.

Os e-mails de alerta não chegam

Use Enviar um e-mail de teste em Definições → Monitorização e alertas; a mensagem mostra a resposta do servidor. Uma palavra-passe só é enviada por STARTTLS ou TLS.

Perguntas frequentes

O RMMZit precisa de um serviço na nuvem?

Não. Tudo corre no seu servidor; nada é enviado para a MaxZit. O servidor apenas consulta o GitHub à procura de novas versões.

Como faço cópia de segurança do RMMZit?

Em Configurações → Backup da consola o servidor guarda todos os dias a base de dados, a chave secreta e os certificados, opcionalmente cifrados e copiados para um servidor SFTP. Guarde uma cópia fora do servidor: sem a chave secreta, as palavras-passe guardadas não podem ser decifradas e os agentes não confiariam num servidor novo.

Posso mudar o servidor para outra máquina?

Sim: instale o RMMZit na nova máquina e restaure lá um backup da consola (rmmzit-server -restore FICHEIRO, no appliance a opção 7 do menu de configuração). Mantenha o mesmo endereço, ou altere o endereço público dos agentes e aponte o nome antigo para a nova máquina; os agentes continuam a funcionar porque o backup contém os certificados do servidor.

O RMMZit é o antigo ControlZit?

Sim. Até à versão 0.12, o RMMZit chamava-se ControlZit. As instalações do ControlZit atualizam-se para o RMMZit como para qualquer nova versão: os dados, os agentes e o seu registo, e os códigos de registo que começam por CZ1- continuam a funcionar.

Existe um agente para macOS?

Ainda não. São suportados Windows e Linux (x86-64, ARM64).

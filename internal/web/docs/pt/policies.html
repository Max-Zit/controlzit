Políticas

Uma política define o Windows Update, o software obrigatório, as regras de alerta e as automações dos clientes, locais ou dispositivos aos quais é atribuída, para que todos os computadores de um escritório ou cliente sejam gerenciados do mesmo jeito.

Partes de uma política

  • Windows Update — o que é instalado automaticamente, em quais dias e a que hora, e se o computador reinicia quando uma atualização precisa.
  • Software obrigatório — programas que todo dispositivo Windows da política deve ter; o servidor instala os que faltam.
  • Regras de alerta — os limites de CPU, memória, discos, dispositivos offline e reinicializações pendentes, Defender e firewall, e os serviços que devem estar em execução.
  • Automações — scripts da biblioteca executados nos dispositivos da política em dias definidos, a uma hora definida.
  • BitLocker — criptografia da unidade do sistema, com a chave de recuperação guardada no servidor.

Cada parte é ativada ou desativada na política. Uma parte desativada não é definida por esta política: vem de uma política menos específica ou dos padrões internos (sem atualizações automáticas, regras de alerta padrão).

Atribuir uma política

As políticas são criadas em Políticas. Na página de uma política, Atribuir a a atribui a um cliente, um local ou um único dispositivo; a guia Política de um dispositivo define a política própria do dispositivo. Um cliente, local ou dispositivo tem uma política; atribuir outra a substitui.

Para cada parte vale a atribuição mais específica que a define: a política do dispositivo, depois a do local, depois a do cliente, depois os padrões internos. Exemplo: a política do cliente define o Windows Update e o software obrigatório, a de um local só regras de alerta mais rígidas — os dispositivos desse local recebem as atualizações e o software do cliente e as regras de alerta do local.

Uma política pertence a um cliente ou ao servidor inteiro, escolha feita na criação. Os técnicos criam e alteram as políticas dos seus clientes e as atribuem a esses clientes, seus locais e dispositivos; os administradores gerenciam todas as políticas, e só eles criam políticas para o servidor inteiro e definem a parte BitLocker. A política de um cliente nunca pode ser atribuída fora desse cliente.

Cada cliente novo recebe sua própria política Default, atribuída a ele, com as configurações internas de Windows Update e alertas; altere-a ou dê aos locais e dispositivos suas próprias políticas. Na atualização para a versão 0.6.3, cada cliente existente sem política recebeu uma política Default com as configurações anteriores do servidor para Windows Update e alertas, que não estão mais em Configurações.

Software obrigatório

Cada programa obrigatório tem uma origem — a biblioteca de software, winget ou Chocolatey — e um texto que o nome dele na lista do Windows de programas instalados contém (por exemplo 7-Zip). A cada poucos minutos o servidor compara os programas obrigatórios com o inventário de cada dispositivo Windows online; um programa que falta é instalado como uma tarefa que você vê na Atividade do dispositivo. Após uma instalação, o dispositivo envia um novo inventário. Se o programa continuar faltando, o servidor tenta de novo após 6 horas. Nada é instalado antes de o dispositivo enviar o primeiro inventário.

Regras de alerta

Os limites de uma política valem para seus dispositivos. Os e-mails de alerta e os canais de chat são definidos para o servidor inteiro em Monitoramento e alertas.

Automações

Uma automação executa um script da biblioteca de scripts nos dias e horário escolhidos (horário do servidor) como uma única tarefa para todos os dispositivos cujas automações vêm desta política. Dispositivos offline a executam quando se conectam, dentro de 24 horas; os resultados ficam na página da tarefa e na Atividade de cada dispositivo.

BitLocker e chaves de recuperação

O servidor guarda as chaves de recuperação do BitLocker dos seus dispositivos Windows: uma vez por dia ele as lê de cada dispositivo com o BitLocker ativado, e Ler as chaves de recuperação agora na página BitLocker do dispositivo (com link na linha BitLocker da visão geral do dispositivo) as lê na hora. As chaves são guardadas criptografadas com a chave secreta do servidor. Só administradores podem mostrar uma chave, depois de digitar a senha; cada chave mostrada e cada senha errada ficam no registro de atividades.

Uma política com Exigir o BitLocker na unidade do sistema o ativa em dispositivos Windows cuja unidade do sistema não está criptografada. O agente primeiro verifica o TPM e adiciona uma chave de recuperação; o servidor guarda a chave e só então a criptografia começa (protetor TPM, XTS-AES 256, só o espaço usado), em segundo plano enquanto o computador é usado. Dispositivos sem TPM pronto ou com uma edição do Windows sem BitLocker (Home) mostram o motivo em Atividade, e o servidor tenta de novo após 6 horas. Administradores também podem ativá-lo para um único dispositivo na página BitLocker dele.

O que vale para um dispositivo

A aba Política de um dispositivo mostra, para cada parte, qual política a define (e se está atribuída ao dispositivo, ao seu local ou ao seu cliente) ou que valem os padrões internos, o estado de cada programa obrigatório (instalado, ausente, quando uma instalação foi iniciada), as configurações de Windows Update e de alertas em vigor e as automações.

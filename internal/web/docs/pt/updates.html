Atualizações do Windows e software

O RMMZit mostra que atualizações faltam em cada computador e instala-as manualmente ou segundo o seu agendamento. Os programas são instalados e atualizados com o winget.

A visão geral

Atualizações lista os dispositivos com atualizações em falta (as de segurança contadas à parte), os dispositivos à espera de reinício, a última instalação e a última pesquisa. Os agentes procuram atualizações em falta alguns minutos depois de arrancar e depois duas vezes por dia; Pesquisar agora inicia uma pesquisa de imediato.

Num dispositivo

O separador Atualizações de um dispositivo lista as atualizações em falta com categoria e gravidade e as instaladas recentemente. Selecione atualizações e clique em Instalar selecionadas; a instalação é executada como tarefa em Atividade, que mostra o resultado quando terminar. Se for preciso reiniciar, o dispositivo indica-o e pode reiniciá-lo a partir da sua página.

As definições do Defender (Security Intelligence Update) saem várias vezes por dia, cada uma com um novo ID de atualização. Quando você instala uma, o agente pesquisa de novo primeiro e instala a versão das definições que o Windows Update oferece naquele momento.

Instalação automática

A parte Windows Update de uma política (por exemplo a política Default do cliente) escolhe o que o servidor instala sozinho:

  • Desligado — as atualizações só são instaladas a partir da consola.
  • Atualizações de segurança e críticas, definições do Defender.
  • Todas as atualizações exceto as de funcionalidades — as novas versões do Windows nunca são instaladas automaticamente.

Escolha os dias e a hora (hora do servidor), ou Na janela de manutenção. Os dispositivos online nesse momento instalam uma vez naquele dia; os offline esperam o próximo dia agendado.

Anel de atualização: com um atraso de, por exemplo, 7 dias, um dispositivo instala uma atualização só 7 dias depois que o servidor a viu pela primeira vez. Dê aos computadores de teste uma política com 0 dias e aos demais uma com 7 dias, e os problemas aparecem primeiro nos computadores de teste. As definições do Defender nunca esperam.

Reiniciar quando uma atualização precisar: nunca automaticamente; automaticamente 5 minutos após a instalação, com um aviso; ou Perguntar ao usuário: o ícone do RMMZit pede ao usuário conectado que reinicie, de novo a cada 4 horas, e após o prazo (os dias que o usuário pode adiar) o servidor reinicia o computador com um aviso de 10 minutos, na janela de manutenção se o dispositivo tiver uma. A aba Política do dispositivo mostra uma reinicialização pendente e o prazo.

Para que as atualizações não cheguem em alturas aleatórias, o agente desliga por política a instalação automática do Windows Update. Quando o agente é removido, as definições anteriores voltam.

Linux

No Linux o agente lê as atualizações de pacotes disponíveis através do apt (Debian, Ubuntu; atualizações de segurança dos repositórios -security) ou do dnf (família RHEL; atualizações de segurança a partir das informações de atualização) e instala os pacotes selecionados. A instalação automática também se aplica aos dispositivos Linux; aí, as «atualizações de segurança» são os pacotes das fontes de segurança.

Programas (winget)

A guia Programas de um dispositivo Windows tem três partes. Atualizações disponíveis lista os programas que o winget pode atualizar; Atualizar tudo os atualiza, ou atualize programas individuais. Instalados lista cada programa da lista do Windows de programas instalados, para o computador e para os usuários conectados, com um filtro por nome ou editor. Desinstalar remove um programa silenciosamente: pacotes do Windows Installer (MSI) com msiexec /x, desinstaladores Inno Setup e NSIS com sua opção silenciosa, ou o comando silencioso do próprio programa. O resultado só é informado quando o programa realmente sumiu; programas sem desinstalador silencioso são marcados e devem ser removidos no computador ou com um script. Instalar um programa pesquisa o repositório da comunidade winget (por exemplo 7-Zip ou Chrome) e instala silenciosamente para todos os usuários. Instalar e atualizar requer o winget (App Installer), que vem com o Windows 10 e 11 atuais.

O Chocolatey pode ser adicionado como segunda fonte pública em Software → Fontes públicas. Instalar um programa passa a oferecer a escolha da fonte (winget ou Chocolatey), e Atualizações disponíveis também lista os programas instalados pelo Chocolatey que têm uma versão mais nova. O cliente Chocolatey é instalado em um dispositivo pelo winget na primeira vez em que é necessário. Os pacotes do Chocolatey são mantidos pela comunidade e geralmente baixam o programa do site do fabricante.

Biblioteca de software

Em Software os administradores enviam seus próprios instaladores: um pacote do Windows Installer (.msi) ou um programa de instalação (.exe), até 2 GB, com nome, versão, os argumentos para uma instalação silenciosa e os códigos de saída que significam sucesso (padrão 0, 1641 e 3010; os dois últimos significam que uma reinicialização conclui a instalação). Para um MSI, o agente executa msiexec /i com um log, e os argumentos padrão são /qn /norestart; um EXE precisa da sua própria opção silenciosa, por exemplo /S (NSIS), /VERYSILENT /NORESTART (Inno Setup) ou /quiet.

Instalar em dispositivos escolhe clientes, locais ou dispositivos Windows individuais e inicia uma tarefa, como um script da biblioteca: dispositivos online instalam imediatamente, os offline quando se conectam dentro de 24 horas. O agente baixa o instalador da porta de agentes do servidor e o confere com o SHA-256 do comando assinado antes de executá-lo como SYSTEM. A página da tarefa mostra o resultado de cada dispositivo; o log de um pacote do Windows Installer é guardado com o resultado. Os técnicos instalam pacotes nos dispositivos dos seus clientes, também por Instalar um programa na guia Programas de um dispositivo.

Vulnerabilidades

Em Vulnerabilidades um administrador liga a verificação dos programas instalados. A cada 6 horas o servidor os compara com bancos de dados públicos de vulnerabilidades: NVD para programas comuns do Windows (navegadores, leitores de PDF, compactadores, ferramentas de acesso remoto e de desenvolvimento e outros) e OSV para os pacotes do Debian e do Ubuntu. Só nomes e versões de programas são enviados, nunca dados dos dispositivos. Uma chave de API do NVD gratuita e opcional acelera a primeira verificação.

A página lista os programas e versões afetados com o número de vulnerabilidades por gravidade e os dispositivos; a aba Vulnerabilidades de um dispositivo lista cada uma com um link para a descrição. Atualizar o programa as corrige. Com Alertar quando um programa tiver uma vulnerabilidade crítica nas regras de alerta de uma política, as críticas (CVSS 9 ou mais) abrem um alerta. O próprio Windows é coberto pelas atualizações do Windows, não por esta verificação.

As vulnerabilidades de pacotes do Debian e do Ubuntu que ainda não têm correção na versão do dispositivo ficam ocultas até você mostrá-las; cada resultado mostra a versão que a corrige.

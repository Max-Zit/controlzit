API

A API REST permite que scripts e outras ferramentas leiam dispositivos, alertas e tarefas e iniciem trabalho nos dispositivos, com os mesmos direitos do console.

Tokens

Crie um token em Minha conta → Tokens de API: um nome, uma função não superior à sua (somente leitura, técnico ou administrador) e por quanto tempo vale. O token é mostrado uma única vez; guarde-o como uma senha. Ele age como você, com seus clientes. Envie-o em cada requisição como Authorization: Bearer czt_… para o endereço do console (porta 8443), que só aceita conexões das redes permitidas. Os cookies de sessão do navegador não funcionam na API. Excluir o token na página da conta encerra o acesso dele na hora.

Tarefas

Uma tarefa aguarda o dispositivo ficar online e é executada depois das tarefas anteriores do dispositivo, assim como as ações no console; ela aparece na Atividade do dispositivo. A resposta é 202 com a tarefa; acompanhe-a com GET /api/v1/tasks/{id} até o status ser done, failed, cancelled ou expired. Os tipos e seus campos:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Exemplos

Um script do PowerShell no dispositivo 9 e depois o resultado:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Erros

Os erros chegam como JSON {"error": "…"} com o status HTTP: 400 para uma requisição inválida, 401 para um token ausente, errado ou expirado, 403 quando a função do token não permite a chamada, 404 para algo que não existe ou que o token não pode ver, 409 quando uma tarefa já terminou, 429 depois de muitas entradas com falha a partir do endereço. Cada alteração pela API fica no registro de atividades com o nome do token.

API

Met de REST-API lezen scripts en andere tools apparaten, waarschuwingen en taken en starten ze werk op apparaten, met dezelfde rechten als in de console.

Tokens

Maak een token onder Mijn account → API-tokens: een naam, een rol die niet hoger is dan de uwe (alleen lezen, technicus of beheerder) en hoe lang het geldig is. Het token wordt één keer getoond; bewaar het als een wachtwoord. Het handelt als u, met uw klanten. Stuur het in elke aanvraag als Authorization: Bearer czt_… naar het consoleadres (poort 8443), dat alleen verbindingen uit de toegestane netwerken aanneemt. Sessiecookies van de browser werken niet op de API. Het token verwijderen op de accountpagina beëindigt de toegang meteen.

Taken

Een taak wacht tot het apparaat online is en loopt na de eerdere taken van het apparaat, net als de acties in de console; ze verschijnt onder Activiteit van het apparaat. Het antwoord is 202 met de taak; volg die met GET /api/v1/tasks/{id} tot de status done, failed, cancelled of expired is. De soorten en hun velden:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Voorbeelden

Een PowerShell-script op apparaat 9, daarna het resultaat:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Fouten

Fouten komen als JSON {"error": "…"} met de HTTP-status: 400 voor een foutieve aanvraag, 401 voor een ontbrekend, onjuist of verlopen token, 403 als de rol van het token de aanroep niet toestaat, 404 voor iets dat niet bestaat of dat het token niet mag zien, 409 als een taak al beëindigd is, 429 na te veel mislukte aanmeldingen vanaf het adres. Elke wijziging via de API wordt met de naam van het token in het activiteitenlogboek vastgelegd.

Probleemoplossing en veelgestelde vragen

De meest gestelde vragen en wat u eerst controleert. Download voor een ondersteuningsverzoek de diagnose onder Instellingen → Diagnose.

Ik kan de console niet bereiken

  • Uw adres staat mogelijk niet in de toegestane netwerken: de verbinding wordt vóór TLS gesloten, dus de browser toont een verbindingsfout. Voer controlzit-server --reset-allowlist uit op de server (appliance: installatiemenu, item 5) om alle privénetwerken weer toe te staan.
  • Open na een poortwijziging de console op de nieuwe poort.
  • Controleer de service op de server: systemctl status controlzit-server en journalctl -u controlzit-server.

Problemen met aanmelden

  • De code is onjuist — de tijd van de telefoon moet kloppen (automatische tijd).
  • Telefoon kwijt — meld u aan met een herstelcode; een andere beheerder kan aanmelden in twee stappen resetten.
  • Te veel mislukte pogingen — het adres is een tijdje geblokkeerd; een beheerder kan het deblokkeren onder Instellingen → Aanmelden en beveiliging. Aanmeldingen vanaf de server zelf worden nooit geblokkeerd.
  • LDAP / eenmalige aanmelding — gebruik Testen op de LDAP-pagina; controleer de groepen die de provider stuurt. Het serverlogboek bevat de details.

Een agent maakt geen verbinding

  • Bereikt de computer de agentpoort? Op Windows: Test-NetConnection rmm.example.com -Port 8444.
  • Klopt het openbare agentadres? Codes die zijn gemaakt terwijl de console via localhost open stond, sturen de agent naar de verkeerde server; stel het adres in en maak een nieuwe code.
  • Is de code nog geldig en niet opgebruikt?
  • Agentlogboeken: Windows C:\ProgramData\ControlZit Agent\agent.log, Linux /var/lib/controlzit-agent/agent.log en journalctl -u controlzit-agent; open ze voor een verbonden apparaat in de console onder Bestanden. Op Windows toont het pictogram naast de klok de verbindingsstatus.

Extern bureaublad toont niets

  • Linux met Wayland kan niet worden getoond: meld u aan met een X11-sessie (Xorg) of gebruik de terminal.
  • Linux zonder bureaublad: gebruik de terminal.
  • Bestanden kopiëren via het klembord vereist een aangemelde gebruiker op de Windows-computer.

Windows-updates worden niet geïnstalleerd

  • Controleer de automatische installatie onder Instellingen → Windows-updates: de dagen, het uur en de modus. Apparaten moeten in dat uur online zijn.
  • Het tabblad Updates van het apparaat toont de laatste zoekopdracht en eventueel de fout.

Waarschuwingsmails komen niet aan

Gebruik Testmail verzenden onder Instellingen → Bewaking en waarschuwingen; het bericht toont het antwoord van de server. Een wachtwoord wordt alleen via STARTTLS of TLS verzonden.

Veelgestelde vragen

Heeft ControlZit een clouddienst nodig?

Nee. Alles draait op uw server; er wordt niets naar MaxZit gestuurd. De server controleert alleen GitHub op nieuwe releases.

Hoe maak ik een back-up van ControlZit?

Maak een back-up van de PostgreSQL-database (pg_dump) en de map /var/lib/controlzit. Zonder de geheime sleutel en de certificaten daarin kunnen opgeslagen wachtwoorden niet worden ontsleuteld en zouden agents een nieuwe server niet vertrouwen.

Kan ik de server naar een nieuwe machine verhuizen?

Ja: installeer ControlZit op de nieuwe machine, zet de database en /var/lib/controlzit terug en houd hetzelfde adres (of wijzig het openbare agentadres en laat de oude naam naar de nieuwe machine wijzen).

Is er een macOS-agent?

Nog niet. Windows en Linux (x86-64, ARM64) worden ondersteund.

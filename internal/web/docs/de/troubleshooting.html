Fehlerbehebung und FAQ

Die häufigsten Fragen und was zuerst zu prüfen ist. Für eine Supportanfrage laden Sie die Diagnose unter Einstellungen → Diagnose herunter.

Ich erreiche die Konsole nicht

  • Ihre Adresse ist eventuell nicht in den erlaubten Netzen: Die Verbindung wird vor TLS geschlossen, der Browser zeigt also einen Verbindungsfehler. Führen Sie controlzit-server --reset-allowlist auf dem Server aus (Appliance: Einrichtungsmenü, Punkt 5), um wieder alle privaten Netze zu erlauben.
  • Nach einer Portänderung öffnen Sie die Konsole auf dem neuen Port.
  • Prüfen Sie den Dienst auf dem Server: systemctl status controlzit-server und journalctl -u controlzit-server.

Probleme bei der Anmeldung

  • Der Code ist falsch — die Uhrzeit des Telefons muss stimmen (automatische Zeit).
  • Telefon verloren — melden Sie sich mit einem Wiederherstellungscode an; ein anderer Administrator kann die Zwei-Faktor-Anmeldung zurücksetzen.
  • Zu viele Fehlversuche — die Adresse ist eine Zeit lang gesperrt; ein Administrator kann sie unter Einstellungen → Anmeldung und Sicherheit entsperren. Anmeldungen vom Server selbst werden nie gesperrt.
  • LDAP / Einmalanmeldung — verwenden Sie Test auf der LDAP-Seite; prüfen Sie die Gruppen, die der Anbieter sendet. Das Serverprotokoll enthält die Details.

Ein Agent verbindet sich nicht

  • Erreicht der Computer den Agent-Port? Unter Windows: Test-NetConnection rmm.example.com -Port 8444.
  • Stimmt die öffentliche Agent-Adresse? Codes, die bei über localhost geöffneter Konsole erstellt wurden, schicken den Agent zum falschen Server; setzen Sie die Adresse und erstellen Sie einen neuen Code.
  • Ist der Code noch gültig und nicht aufgebraucht?
  • Agent-Protokolle: Windows C:\ProgramData\ControlZit Agent\agent.log, Linux /var/lib/controlzit-agent/agent.log und journalctl -u controlzit-agent; bei einem verbundenen Gerät öffnen Sie sie in der Konsole unter Dateien. Unter Windows zeigt das Symbol neben der Uhr den Verbindungsstatus.

Die Fernsteuerung zeigt nichts

  • Linux mit Wayland kann nicht angezeigt werden: Melden Sie sich mit einer X11-Sitzung (Xorg) an oder verwenden Sie das Terminal.
  • Linux ohne Desktop: Verwenden Sie das Terminal.
  • Dateien über die Zwischenablage zu kopieren braucht einen angemeldeten Benutzer am Windows-Computer.

Windows-Updates werden nicht installiert

  • Prüfen Sie die automatische Installation im Reiter Richtlinie des Geräts: welche Richtlinie Windows Update festlegt, die Tage, die Stunde und den Modus. Die Geräte müssen in dieser Stunde online sein.
  • Die Registerkarte Updates des Geräts zeigt die letzte Suche und gegebenenfalls ihren Fehler.

Alarm-E-Mails kommen nicht an

Verwenden Sie Test-E-Mail senden unter Einstellungen → Überwachung und Alarme; die Meldung zeigt die Antwort des Servers. Ein Passwort wird nur über STARTTLS oder TLS gesendet.

FAQ

Braucht ControlZit einen Cloud-Dienst?

Nein. Alles läuft auf Ihrem Server; nichts wird an MaxZit gesendet. Der Server prüft nur GitHub auf neue Versionen.

Wie sichere ich ControlZit?

Unter Einstellungen → Konsolensicherung sichert der Server täglich seine Datenbank, den geheimen Schlüssel und die Zertifikate, auf Wunsch verschlüsselt und auf einen SFTP-Server kopiert. Bewahren Sie eine Kopie außerhalb des Servers auf: Ohne den geheimen Schlüssel lassen sich gespeicherte Kennwörter nicht entschlüsseln, und Agenten würden einem neuen Server nicht vertrauen.

Kann ich den Server auf einen neuen Rechner umziehen?

Ja: Installieren Sie ControlZit auf dem neuen Rechner und stellen Sie dort eine Konsolensicherung wieder her (controlzit-server -restore DATEI, auf der Appliance Punkt 7 des Setup-Menüs). Behalten Sie dieselbe Adresse oder ändern Sie die öffentliche Agentenadresse und leiten Sie den alten Namen auf den neuen Rechner; die Agenten arbeiten weiter, weil die Sicherung die Zertifikate des Servers enthält.

Gibt es einen macOS-Agent?

Noch nicht. Unterstützt werden Windows und Linux (x86-64, ARM64).

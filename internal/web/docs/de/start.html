Erste Schritte

ControlZit ist ein selbst gehostetes Werkzeug zur Fernüberwachung und -verwaltung (RMM). Von einer Webkonsole auf Ihrem eigenen Server überwachen und verwalten Sie die Windows- und Linux-Computer Ihrer Kunden: Inventar, Überwachung und Alarme, Fernsteuerung, Terminal, Dateien, Skripte, Windows-Updates, Software und Berichte.

Was ControlZit kann

BereichWas Sie bekommen
InventarHardware, Betriebssystem, Datenträger, Netzwerk, Sicherheitsstatus (Virenschutz, Firewall, BitLocker) und installierte Software jedes Geräts. Geräte
Überwachung und AlarmeCPU, Arbeitsspeicher, Speicherplatz, Offline-Geräte, gestoppte Dienste, Defender und Firewall; Alarme per E-Mail, Slack, Microsoft Teams oder Webhook. Überwachung
FernzugriffFernsteuerung im Browser (Windows, Linux mit X11) mit Zwischenablage und Dateikopie, Root-Terminal unter Linux, Dateimanager, Prozesse, Dienste, Neustart und Herunterfahren. Fernzugriff
SkriptePowerShell, cmd, bash oder sh auf einem Gerät, auf vielen Geräten gleichzeitig oder nach Zeitplan, aus einer Skriptbibliothek. Skripte
Updates und SoftwareFehlende Windows-Updates und Linux-Pakete, Installation von Hand oder nach Zeitplan, Programme über winget. Updates
BerichteEin Bericht pro Kunde (Geräte, Updates, Alarme, Arbeit der Techniker), druckbar oder wöchentlich bzw. monatlich per E-Mail. Berichte

So funktioniert es

  • Der Server läuft auf einem Linux-Rechner (meist einer kleinen VM) mit PostgreSQL. Er hat zwei Ports: die Konsole (Weboberfläche und API, TCP 8443) und den Agent-Endpunkt (TCP 8444).
  • Agents laufen als Dienst auf jedem verwalteten Computer. Sie verbinden sich ausgehend mit dem Agent-Port; die Computer brauchen keine offenen Ports. Ein Agent vertraut dem Server anhand des Fingerabdrucks seines Zertifikats, den er bei der Registrierung fixiert.
  • Jeder Befehl an einen Agent wird vom Server signiert und vom Agent geprüft, und jede Aktion wird im manipulationssicheren Prüfprotokoll vermerkt.

Die Konsole steuert jeden verwalteten Computer. Machen Sie sie nur aus Ihren eigenen Netzen erreichbar (Standard) und öffnen Sie nur den Agent-Port dort, wo Agents ihn brauchen. Siehe Sicherheit.

Erste Schritte

  1. Server installieren — fertiges VM-Image importieren, Appliance-ISO starten oder das Installationsskript auf einem Linux-Server ausführen. Siehe Server installieren.
  2. Ersten Administrator anlegen mit dem Einrichtungstoken, das der Server anzeigt, und die Zwei-Faktor-Anmeldung mit einer Authenticator-App einrichten.
  3. Agent-Adresse prüfen unter Einstellungen → Netzwerk und Zugriff: Agents müssen den Server über die öffentliche Agent-Adresse oder den Hostnamen der Konsole erreichen.
  4. Kunden und Standort anlegen unter Kunden und am Standort einen Registrierungscode erstellen.
  5. Agent installieren auf den Computern dieses Standorts mit dem Code. Siehe Agents installieren.
  6. Alarme einrichten unter Einstellungen → Überwachung und Alarme und, wenn gewünscht, die automatische Installation von Windows-Updates.
  7. Techniker hinzufügen unter Benutzer oder Active Directory / LDAP bzw. Einmalanmeldung anbinden. Siehe Benutzer, Rollen und Anmeldung.

Voraussetzungen

  • Server: 2 vCPU, 2–4 GB RAM, 16 GB Festplatte; Debian 12+, Ubuntu 22.04+, AlmaLinux oder Rocky Linux 9+ (oder die fertige Appliance).
  • Windows-Agents: Windows 10 / 11, Windows Server 2016 und neuer, 64-Bit.
  • Linux-Agents: Distributionen mit systemd, x86-64 oder ARM64 (Raspberry Pi und ARM-Server). Updates über apt oder dnf.
  • Browser: ein aktueller Chrome, Edge, Firefox oder Safari.

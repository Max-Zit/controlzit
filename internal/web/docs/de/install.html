Server installieren

Wählen Sie einen von fünf Wegen. Das fertige VM-Image ist am schnellsten; das Installationsskript passt zu einem vorhandenen Linux-Server, Docker zu einem vorhandenen Docker-Host.

WegAm besten fürBraucht
1. VM-Image (OVA, qcow2, VHDX)importieren, starten, anmelden, in wenigen MinutenVMware, Proxmox / KVM oder Hyper-V

Alle Dateien liegen auf der Versionsseite. Geben Sie dem Server 2 vCPU, 2–4 GB RAM und eine Festplatte ab 16 GB.

1. VM-Image

  1. Image importieren:
    • VMware ESXi / Workstation, VirtualBox: rmmzit-appliance.ova bereitstellen (Create / Register VM → Deploy a virtual machine from an OVF or OVA file).
    • Proxmox VE: eine VM ohne Festplatte anlegen (2 vCPU, 2–4 GB RAM, VirtIO-Netzwerk), rmmzit-appliance.qcow2 auf den Knoten kopieren und qm importdisk <vmid> rmmzit-appliance.qcow2 local-lvm ausführen; die Festplatte als SCSI anhängen und zur Bootplatte machen.
    • Hyper-V: rmmzit-appliance-vhdx.zip entpacken und eine VM der Generation 1 mit der VHDX als Festplatte anlegen.
  2. VM starten. Die Festplatte wächst von selbst auf die Größe der virtuellen Festplatte. Der Bildschirm der VM zeigt die Adresse der Konsole und das Einrichtungstoken.
  3. https://<Adresse>:8443 öffnen. Der Browser warnt einmal vor dem selbstsignierten Zertifikat (später unter Einstellungen → Zertifikat ersetzen). Einrichtungstoken eingeben und den ersten Administrator anlegen.

Die Appliance bezieht ihre Adresse per DHCP. Für eine feste Adresse, den Servernamen oder die Zeitzone melden Sie sich am Bildschirm der VM als rzadmin an (erstes Passwort rmmzit, muss geändert werden): Ein Einrichtungsmenü öffnet sich. Zeitzone und Netzwerk lassen sich später auch in der Konsole ändern.

2. Appliance-ISO

  1. Eine VM oder einen Server von rmmzit-appliance.iso starten. Nach 5 Sekunden beginnt die Installation von selbst: Sie löscht die erste Festplatte, installiert Debian, PostgreSQL und RMMZit und braucht Internetzugang (10–20 Minuten).
  2. Nach dem Neustart zeigt der Bildschirm die Konsolenadresse und das Einrichtungstoken, wie beim VM-Image.

3. Installationsskript

Auf einem vorhandenen Linux-Server als root:

curl -fsSL https://github.com/Max-Zit/rmmzit/releases/latest/download/install.sh | sudo sh

Das Skript installiert PostgreSQL, lädt die neueste Version, prüft ihre Signatur, legt eine Datenbank mit Zufallspasswort an und startet den Dienst. Optionen (nach sh -s --): --version X, --db postgres://… für eine vorhandene Datenbank, --no-auto-updates, um die automatischen Sicherheitsupdates des Betriebssystems ausgeschaltet zu lassen. Ein erneuter Lauf aktualisiert RMMZit und behält die Daten.

4. Pakete von Hand

sudo apt install ./rmmzit-server_X_amd64.deb      # Debian, Ubuntu
sudo dnf install ./rmmzit-server-X-1.x86_64.rpm     # AlmaLinux, Rocky Linux

Tragen Sie dann die Datenbankadresse in /etc/rmmzit/server.env ein (RMMZIT_DB=postgres://…) und starten Sie den Dienst mit systemctl enable --now rmmzit-server.

5. Docker

Den Server gibt es auch als Container-Image, ghcr.io/max-zit/rmmzit, gebaut aus demselben signierten Serverpaket wie die anderen Wege und mit PostgreSQL über Docker Compose betrieben. Laden Sie docker-compose.yml und .env.example in einen Ordner, kopieren Sie .env.example nach .env, setzen Sie ein Datenbankpasswort (Buchstaben und Ziffern) und die Zeitzone, dann:

docker compose up -d
docker compose exec rmmzit cat /var/lib/rmmzit/setup-token.txt

Öffnen Sie https://<host>:8443 und geben Sie das Setup-Token ein. Port 8444 ist der Agenten-Endpunkt; öffnen Sie ihn dort, von wo Agenten sich verbinden. Der Image-Tag in .env bestimmt, was läuft: latest für offizielle Versionen, testing für Release-Kandidaten.

Aktualisieren Sie mit docker compose pull && docker compose up -d. Bevor eine neue Version die Datenbank ändert, schreibt der Server eine Sicherung nach Einstellungen → Konsolensicherung. Um zurückzugehen, setzen Sie die vorherige Version als Image-Tag und stellen diese Datei wieder her: docker compose stop rmmzit, docker compose run --rm rmmzit -restore /var/lib/rmmzit/backups/DATEI, docker compose up -d. Im Container gehören Netzwerk und Zeitzone zum Docker-Host, nicht zur Konsole.

Erste Anmeldung

  • Das Einrichtungstoken steht in /var/lib/rmmzit/setup-token.txt und im Serverprotokoll (journalctl -u rmmzit-server). Es gilt einmal.
  • Jedes Konto braucht eine Authenticator-App (TOTP) und erhält 10 Wiederherstellungscodes. Bewahren Sie sie sicher auf.
  • Die Konsole nimmt standardmäßig nur Verbindungen aus privaten Netzen an. Wenn Sie sich aussperren, führen Sie rmmzit-server --reset-allowlist auf dem Server aus (Appliance: Einrichtungsmenü, Punkt 5).

Wo was liegt

PfadWas
/etc/rmmzit/server.envKonfiguration: Datenbank, Ports, Update-Quelle (nur für root und den Dienst lesbar)
/var/lib/rmmzitDatenverzeichnis: Zertifikate, geheimer Schlüssel, Agent-Installationsprogramme (downloads), Protokolle
/var/lib/rmmzit/logs/server.logServerprotokoll; auch in journalctl -u rmmzit-server
/var/log/rmmzit-helperProtokoll des Root-Helfers (Updates, Zeitzone, Netzwerk)

Sichern Sie die Datenbank zusammen mit /var/lib/rmmzit: Der geheime Schlüssel dort entschlüsselt die gespeicherten Passwörter, und die Zertifikate weisen den Server gegenüber seinen Agents aus.

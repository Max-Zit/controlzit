Richtlinien

Eine Richtlinie legt Windows Update, erforderliche Software, Alarmregeln und Automatisierungen für die Kunden, Standorte oder Geräte fest, denen sie zugewiesen ist, damit alle Computer eines Büros oder Kunden gleich verwaltet werden.

Teile einer Richtlinie

  • Windows Update — was automatisch installiert wird, an welchen Tagen und zu welcher Stunde, und ob der Computer neu startet, wenn ein Update es braucht.
  • Erforderliche Software — Programme, die jedes Windows-Gerät der Richtlinie haben muss; fehlende installiert der Server.
  • Alarmregeln — die Schwellen für CPU, Speicher, Datenträger, Offline-Geräte und ausstehende Neustarts, Defender und Firewall sowie die Dienste, die laufen müssen.
  • Automatisierungen — Bibliotheksskripte, die an festgelegten Tagen zu einer festgelegten Zeit auf den Geräten der Richtlinie laufen.
  • BitLocker — Verschlüsselung des Systemlaufwerks, der Wiederherstellungsschlüssel bleibt auf dem Server.
  • Programm-Updates — Aktualisieren der installierten Programme, die winget oder Chocolatey kennen, an festgelegten Tagen oder im Wartungsfenster.
  • Wartungsfenster — wann die Geräte beschäftigt sein dürfen: Installationen, erzwungene Neustarts und auf Wunsch keine neuen Alarme.

Jeder Teil wird in der Richtlinie ein- oder ausgeschaltet. Ein ausgeschalteter Teil wird von dieser Richtlinie nicht festgelegt: Er kommt aus einer weniger spezifischen Richtlinie oder aus den eingebauten Standardwerten (keine automatischen Updates, Standard-Alarmregeln).

Eine Richtlinie zuweisen

Richtlinien werden unter Richtlinien angelegt. Auf der Seite einer Richtlinie weist Zuweisen an sie einem Kunden, einem Standort oder einem einzelnen Gerät zu; die Registerkarte Richtlinie eines Geräts legt die eigene Richtlinie des Geräts fest. Ein Kunde, Standort oder Gerät hat eine Richtlinie; eine andere zuzuweisen ersetzt sie.

Für jeden Teil gilt die spezifischste Zuweisung, die ihn festlegt: die Richtlinie des Geräts, dann die des Standorts, dann die des Kunden, dann die eingebauten Standardwerte. Beispiel: Die Richtlinie des Kunden legt Windows Update und erforderliche Software fest, die Richtlinie eines Standorts nur strengere Alarmregeln — die Geräte dieses Standorts erhalten Updates und Software des Kunden und die Alarmregeln des Standorts.

Eine Richtlinie gehört entweder einem Kunden oder dem ganzen Server; das wird beim Anlegen gewählt. Techniker legen die Richtlinien ihrer Kunden an, ändern sie und weisen sie diesen Kunden, ihren Standorten und Geräten zu; Administratoren verwalten alle Richtlinien, und nur sie legen serverweite Richtlinien an und setzen den Teil BitLocker. Die Richtlinie eines Kunden kann nie außerhalb dieses Kunden zugewiesen werden.

Jeder neue Kunde erhält eine eigene Richtlinie Default, ihm zugewiesen, mit den eingebauten Einstellungen für Windows Update und Alarme; ändern Sie sie oder geben Sie Standorten und Geräten eigene Richtlinien. Beim Update auf Version 0.6.3 hat jeder bestehende Kunde ohne Richtlinie eine Richtlinie Default mit den bisherigen Server-Einstellungen für Windows Update und Alarme erhalten, die es unter Einstellungen nicht mehr gibt.

Erforderliche Software

Jedes erforderliche Programm hat eine Quelle — die Softwarebibliothek, winget oder Chocolatey — und einen Text, den sein Name in der Windows-Liste der installierten Programme enthält (zum Beispiel 7-Zip). Alle paar Minuten vergleicht der Server die erforderlichen Programme mit dem Inventar jedes Windows-Geräts, das online ist; ein fehlendes Programm wird als Aufgabe installiert, die Sie unter Aktivität des Geräts sehen. Nach einer Installation sendet das Gerät ein neues Inventar. Fehlt das Programm weiterhin, versucht es der Server nach 6 Stunden erneut. Bevor ein Gerät sein erstes Inventar gesendet hat, wird nichts installiert.

Alarmregeln

Die Schwellenwerte einer Richtlinie gelten für ihre Geräte. Alarm-E-Mails und Chat-Kanäle werden für den ganzen Server unter Überwachung und Alarme festgelegt.

Automatisierungen

Eine Automatisierung führt ein Skript der Skriptbibliothek an den gewählten Tagen und zur gewählten Zeit (Serverzeit) als einen Auftrag für alle Geräte aus, deren Automatisierungen aus dieser Richtlinie kommen. Offline-Geräte führen es aus, wenn sie sich verbinden, innerhalb von 24 Stunden; die Ergebnisse stehen auf der Seite des Auftrags und unter Aktivität jedes Geräts.

BitLocker und Wiederherstellungsschlüssel

Der Server bewahrt die BitLocker-Wiederherstellungsschlüssel seiner Windows-Geräte auf: Einmal täglich liest er sie von jedem Gerät mit eingeschaltetem BitLocker, und Wiederherstellungsschlüssel jetzt lesen auf der BitLocker-Seite des Geräts (verlinkt in der BitLocker-Zeile der Geräteübersicht) liest sie sofort. Die Schlüssel werden mit dem geheimen Schlüssel des Servers verschlüsselt gespeichert. Nur Administratoren können einen Schlüssel anzeigen, nach Eingabe ihres Kennworts; jeder angezeigte Schlüssel und jedes falsche Kennwort wird im Aktivitätsprotokoll festgehalten.

Eine Richtlinie mit BitLocker auf dem Systemlaufwerk verlangen schaltet es auf Windows-Geräten ein, deren Systemlaufwerk nicht verschlüsselt ist. Der Agent prüft zuerst das TPM und fügt einen Wiederherstellungsschlüssel hinzu; der Server speichert den Schlüssel, und erst dann beginnt die Verschlüsselung (TPM-Schutz, XTS-AES 256, nur belegter Speicher) im Hintergrund, während der Computer genutzt wird. Geräte ohne bereites TPM oder mit einer Windows-Edition ohne BitLocker (Home) zeigen den Grund unter Aktivität, und der Server versucht es nach 6 Stunden erneut. Administratoren können es auch für ein einzelnes Gerät auf dessen BitLocker-Seite einschalten.

Programm-Updates

Der Teil Programm-Updates aktualisiert die installierten Programme mit einer neueren Version: die, die winget kennt, und auf Wunsch die mit Chocolatey installierten. Er läuft einmal an jedem gewählten Tag zur gewählten Stunde oder im Wartungsfenster. Programme auf der Liste Nicht aktualisieren (Paket-IDs oder Namensteile) bleiben unverändert. Mit einer Verzögerung im Update-Ring wartet eine neue Version so viele Tage, nachdem der Server sie zuerst gesehen hat. Jeder Lauf erscheint unter der Aktivität des Geräts.

Wartungsfenster

Ein Wartungsfenster ist ein wöchentlicher Zeitraum, zum Beispiel samstags ab 22:00 für 4 Stunden (Serverzeit). Windows-Updates und Programm-Updates mit Im Wartungsfenster laufen dann, und ein Neustart nach Ablauf der Frist wartet auf das nächste Fenster. Mit Keine neuen Alarme während eines Wartungsfensters öffnen die Geräte keine neuen Alarme, solange ein Fenster offen ist; bereits offene Alarme bleiben bestehen.

Was für ein Gerät gilt

Der Reiter Richtlinie eines Geräts zeigt für jeden Teil, welche Richtlinie ihn festlegt (und ob sie dem Gerät, seinem Standort oder seinem Kunden zugewiesen ist) oder dass die eingebauten Standardwerte gelten, den Zustand jedes erforderlichen Programms (installiert, fehlt, wann eine Installation gestartet wurde), die geltenden Einstellungen für Windows Update und Alarme sowie die Automatisierungen.

Sicherheit

Ein RMM-Server kann jeden Computer steuern, den er verwaltet. RMMZit ist so gebaut, dass ein Angreifer, der die Konsole, das Netz oder sogar den Server erreicht, so wenig wie möglich bekommt.

Wie RMMZit Sie schützt

  • Zwei Ports. Konsole und Agent-Endpunkt lauschen auf getrennten Ports. Die Konsole nimmt nur Verbindungen aus erlaubten Netzen an, geprüft vor TLS; der Agent-Port kann öffentlich sein, ohne die Konsole freizugeben.
  • Ausgehende Agents. Agents verbinden sich mit dem Server; verwaltete Computer brauchen keine offenen Ports. Agents fixieren das Serverzertifikat anhand seines Fingerabdrucks, sodass ein gefälschter Server sie nicht übernehmen kann.
  • Signierte Befehle. Jeder Befehl an einen Agent wird mit dem Befehlsschlüssel des Servers signiert und vom Agent geprüft; Agent-Updates müssen zum SHA-256 in einem signierten Befehl passen.
  • Starke Anmeldung. Zwei-Faktor-Anmeldung für jedes lokale und Verzeichniskonto, argon2id-Passwörter, kurze Sitzungen, Abmeldung nach Inaktivität, zunehmende Sperren fehlgeschlagener Anmeldungen.
  • Browser-Schutz. CSRF-Prüfungen bei jeder Änderung, eine strikte Content Security Policy ohne Inline-Skripte, __Host--Sitzungscookies.
  • Geringste Rechte. Rollen und Zugriff pro Kunde; die Konsole läuft als nicht privilegierter Benutzer, und die wenigen Root-Aktionen (Updates, Netzwerk, Zeitzone) laufen über einen getrennten Root-Helfer, der nur feste, geprüfte Anfragen annimmt.
  • Prüfung. Ein per Hash verkettetes Prüfprotokoll jeder Änderung und jeder Fernaktion.
  • Signierte Versionen. Server, Agents und install.sh installieren nur Versionen, die mit dem RMMZit-Release-Schlüssel signiert sind.
  • Geheimnisse. Gespeicherte Passwörter (E-Mail, LDAP, Kanäle, Cloudflare) werden mit dem geheimen Schlüssel des Servers verschlüsselt; die Diagnose entfernt Geheimnisse.

Empfehlungen

  1. Machen Sie die Konsole nur aus Ihren Admin-Netzen erreichbar; verwenden Sie für den Zugriff von außen ein VPN (zum Beispiel WireGuard), statt den Konsolen-Port zu öffnen.
  2. Öffnen Sie den Agent-Port nur dort, wo Agents sind, und setzen Sie die Agent-Netze, wenn alle Agents von bekannten Adressen kommen.
  3. Verwenden Sie ein Zertifikat, dem Browser vertrauen (Let's Encrypt oder Ihre CA), damit Benutzer sich nicht angewöhnen, Warnungen wegzuklicken.
  4. Geben Sie jeder Person ein eigenes Konto mit der kleinsten Rolle und nur den Kunden, die sie braucht; deaktivieren Sie Konten von Personen, die gehen.
  5. Behalten Sie einen lokalen Administrator für Notfälle, mit offline aufbewahrten Wiederherstellungscodes.
  6. Installieren Sie RMMZit-Updates zügig (oder schalten Sie automatische Updates ein) und halten Sie das Betriebssystem des Servers aktuell; die Appliance installiert Debian-Sicherheitsupdates selbst.
  7. Sichern Sie die Datenbank und /var/lib/rmmzit regelmäßig und bewahren Sie die Sicherung getrennt vom Server auf.
  8. Prüfen Sie das Prüfprotokoll von Zeit zu Zeit und lassen Sie den Hinweis auf dem entfernten Bildschirm an, damit Benutzer wissen, wann jemand verbunden ist.

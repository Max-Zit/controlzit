API

Mit der REST-API lesen Skripte und andere Werkzeuge Geräte, Alarme und Aufgaben und starten Arbeiten auf Geräten, mit denselben Rechten wie in der Konsole.

Tokens

Erstellen Sie ein Token unter Mein Konto → API-Tokens: einen Namen, eine Rolle, die nicht höher als Ihre ist (nur lesen, Techniker oder Administrator), und wie lange es gilt. Das Token wird einmal angezeigt; bewahren Sie es wie ein Kennwort auf. Es handelt als Sie, mit Ihren Kunden. Senden Sie es in jeder Anfrage als Authorization: Bearer czt_… an die Konsolenadresse (Port 8443), die nur Verbindungen aus den erlaubten Netzen annimmt. Sitzungscookies des Browsers funktionieren bei der API nicht. Das Token auf der Kontoseite zu löschen, beendet seinen Zugriff sofort.

Aufgaben

Eine Aufgabe wartet, bis das Gerät online ist, und läuft nach den früheren Aufgaben des Geräts, genau wie die Aktionen in der Konsole; sie erscheint unter Aktivität des Geräts. Die Antwort ist 202 mit der Aufgabe; verfolgen Sie sie mit GET /api/v1/tasks/{id}, bis ihr Status done, failed, cancelled oder expired ist. Die Arten und ihre Felder:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Beispiele

Ein PowerShell-Skript auf Gerät 9, dann sein Ergebnis:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Fehler

Fehler kommen als JSON {"error": "…"} mit dem HTTP-Status: 400 für eine fehlerhafte Anfrage, 401 für ein fehlendes, falsches oder abgelaufenes Token, 403, wenn die Rolle des Tokens den Aufruf nicht erlaubt, 404 für etwas, das nicht existiert oder das das Token nicht sehen darf, 409, wenn eine Aufgabe bereits beendet ist, 429 nach zu vielen fehlgeschlagenen Anmeldungen von der Adresse. Jede Änderung über die API wird mit dem Namen des Tokens im Aktivitätsprotokoll festgehalten.

Servereinstellungen und Updates

Administratoren finden die Einstellungen des Servers unter Einstellungen: Netzwerk und Ports, das Zertifikat, Zeitzone, Updates von Server und Agents und die Diagnose für den Support.

Netzwerk und Zugriff

Unter Einstellungen → Netzwerk und Zugriff:

  • Konsole — Lauschadresse und Port (Standard :8443) und die erlaubten Netze: eine IP-Adresse oder ein Netz pro Zeile (CIDR). Verbindungen von anderen Adressen werden vor TLS geschlossen; der Server selbst (127.0.0.1) ist immer erlaubt. Das Speichern verweigert eine Liste, die Ihre eigene Adresse aussperren würde.
  • Agent-Endpunkt — Lauschadresse und Port (Standard :8444, muss sich von der Konsole unterscheiden), die Netze, aus denen Agents kommen dürfen (leer = alle), und die öffentliche Agent-Adresse, die in Installationsprogramme und Registrierungscodes eingetragen wird.
  • Neue Ports gelten nach Jetzt neu starten (startet den RMMZit-Dienst neu; Agents verbinden sich von selbst wieder).

Wenn Sie sich aussperren, führen Sie rmmzit-server --reset-allowlist auf dem Server aus (Appliance: Einrichtungsmenü, Punkt 5).

Netzwerk des Servers (Appliance)

Auf der RMMZit-Appliance wird hier auch das eigene Netzwerk des Servers eingestellt: DHCP oder eine feste Adresse mit Netzgröße (z. B. 192.168.1.20/24), Gateway, ein bis drei DNS-Server und der Servername. Antwortet das Gateway mit den neuen Einstellungen nicht, kehren die vorherigen nach 30 Sekunden von selbst zurück. Bei anderen Installationen verwaltet das Betriebssystem das Netzwerk.

Zeitzone

Zeitpläne (Updates, Skripte, Berichte) und die Zeiten in der Konsole verwenden die Zeitzone des Servers. Wählen Sie sie aus der Liste und klicken Sie auf Festlegen; die Konsole startet neu und ist in wenigen Sekunden zurück. Ohne Root-Helfer (siehe unten) stellen Sie sie auf dem Server ein: timedatectl set-timezone Europe/Berlin.

Zertifikat (HTTPS)

Unter Einstellungen → Zertifikat wählen Sie das Zertifikat, das Browser beim Öffnen der Konsole sehen. Agents verwenden ihren eigenen Port und ihr eigenes Zertifikat, eine Änderung trennt sie daher nie.

  • Das eigene Zertifikat der Konsole (selbstsigniert) — funktioniert sofort; Browser warnen davor.
  • Let's Encrypt — ein kostenloses Zertifikat, automatisch 30 Tage vor Ablauf erneuert. Geben Sie den öffentlichen DNS-Namen der Konsole und eine E-Mail-Adresse ein und wählen Sie die Prüfung:
    • Port 80 — der Name zeigt auf diesen Server und Port 80 ist aus dem Internet erreichbar; der Server antwortet auf Port 80 und leitet Browser auf HTTPS um;
    • Cloudflare-DNS — für Server, die aus dem Internet nicht erreichbar sind; braucht ein Cloudflare-API-Token mit Zone:DNS:Edit für die Zone.
  • Zertifikat hochladen von Ihrer Zertifizierungsstelle oder Unternehmens-CA: das Zertifikat (PEM, mit Zwischenzertifikaten) und den privaten Schlüssel. Der Schlüssel wird nur auf diesem Server gespeichert.

Updates des Servers

Einstellungen → RMMZit-Updates zeigt die laufende Version und die neueste Version. Installieren aktualisiert den Server: Es werden nur Versionen installiert, die mit dem RMMZit-Release-Schlüssel signiert sind; vor der Installation sichert der Server Datenbank und Programm, und startet die neue Version nicht, kehrt er von selbst zur alten zurück. Die Konsole ist ein bis zwei Minuten weg. Optional werden neue Versionen automatisch in einer gewählten Stunde installiert.

Update-Kanal: Offizielle Versionen (Standard) oder Test, der Release-Kandidaten anbietet, bevor sie offiziell werden, für eine Testkonsole. Produktive Konsolen bleiben bei offiziellen Versionen.

Updates, Zeitzone und Netzwerk brauchen den Root-Helfer, der mit den Linux-Paketen und der Appliance kommt. Ohne ihn (z. B. das reine Programm) aktualisieren Sie mit install.sh oder dem Paket der Version.

Agent-Updates

Siehe Agents installieren → Agent-Updates.

Diagnose

Einstellungen → Diagnose zeigt, wo RMMZit seine Protokolle schreibt, die neuesten Zeilen des Serverprotokolls (Filter nach Ebene oder Text), das Protokoll des Root-Helfers und die Versionen. Diagnose herunterladen (ZIP) erstellt eine Datei für den Support mit den Protokollen, den Versionen und einer Zusammenfassung der Einstellungen, den Geräten, den Alarmen und dem Prüfprotokoll. Passwörter, Tokens, Registrierungscodes und Schlüssel werden aus allem Angezeigten und aus der Datei entfernt; Skripte und ihre Ausgabe sind nicht enthalten.

Eigene Felder

Unter Einstellungen → Eigene Felder legen Administratoren eigene Felder für Geräte und Kunden an — Text, Zahl oder Datum —, zum Beispiel eine Inventarnummer, das Garantieende oder einen Vertrag. Techniker füllen sie auf den Seiten der Geräte und Kunden aus; die API liefert die Gerätefelder mit jedem Gerät und setzt sie mit PUT /api/v1/devices/{id}/fields.

Konsolensicherung

Einstellungen → Konsolensicherung sichert die Konsole jeden Tag zur gewählten Stunde oder sofort mit Jetzt sichern. Eine Sicherung enthält die Datenbank, den geheimen Schlüssel der gespeicherten Passwörter, die Zertifikate und Schlüssel, denen die Agenten vertrauen, und die Software-Bibliothek. Die neuesten Sicherungen (so viele Sie wählen) bleiben im Ordner backups des Datenverzeichnisses und lassen sich von der Seite herunterladen.

Mit einer Passphrase werden die Dateien verschlüsselt (AES-256-GCM); bewahren Sie die Passphrase woanders auf, denn ohne sie lässt sich eine Sicherung nicht wiederherstellen. Eine Kopie jeder Sicherung kann in einen SFTP-Ordner auf einem anderen Server gehen (Passwort oder privater Schlüssel). Der erste Test der Verbindung zeigt den Host-Schlüssel des Servers zum Vertrauen; Kopien gehen nur an einen Server mit diesem Schlüssel. Schlägt eine Sicherung oder ihre Kopie fehl, erhalten die Empfänger der Warn-E-Mails eine E-Mail.

Eine Wiederherstellung läuft bei gestopptem Server: auf der Appliance im Setup-Menü (Restore a backup), mit den Linux-Paketen:

sudo systemctl stop rmmzit-server
sudo -u rmmzit sh -c 'set -a; . /etc/rmmzit/server.env; rmmzit-server -data-dir /var/lib/rmmzit -restore /path/rmmzit-backup-….czb'
sudo systemctl start rmmzit-server

Die Passphrase einer verschlüsselten Sicherung wird aus RMMZIT_BACKUP_PASSPHRASE oder aus einer mit -restore-passphrase-file angegebenen Datei gelesen. Die Datenbank wird in einem Schritt wiederhergestellt (schlägt das fehl, ändert sich nichts); eine neuere RMMZit-Version aktualisiert die wiederhergestellte Datenbank beim Start. Ein aus einer Sicherung wiederhergestellter neuer Server behält alle Agenten, weil sie demselben Zertifikat vertrauen.

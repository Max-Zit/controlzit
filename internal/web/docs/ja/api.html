API

REST API を使うと、スクリプトやその他のツールがコンソールと同じ権限で、デバイス、アラート、タスクを読み取り、デバイスで作業を開始できます。

トークン

アカウント → API トークンでトークンを作成します。名前、あなたのロールを超えないロール（読み取り専用、技術者、管理者）、有効期間を指定します。トークンは 1 回だけ表示されるので、パスワードと同じように保管してください。トークンはあなたとして、あなたの顧客の範囲で動作します。すべての要求で Authorization: Bearer czt_… としてコンソールのアドレス（ポート 8443）に送信します。このアドレスは許可されたネットワークからの接続だけを受け付けます。ブラウザーのセッション Cookie は API では使えません。アカウント ページでトークンを削除すると、すぐにアクセスできなくなります。

呼び出し

呼び出し内容
GET /api/v1/meトークンが誰として動作するか、そのロールと顧客
GET /api/v1/customers顧客
GET /api/v1/customers/{id}/sites顧客のサイト
GET /api/v1/devices?customer=&site=&q=デバイス（顧客、サイト、検索文字で絞り込み可能）
GET /api/v1/devices/{id}インベントリ付きの 1 台のデバイス
GET /api/v1/devices/{id}/tasksデバイスのタスク（実行中、待機中、最近完了した 100 件）
POST /api/v1/devices/{id}/tasksデバイスでタスクを開始（技術者）
GET /api/v1/tasks/{id}終了まで追跡するための 1 件のタスク
POST /api/v1/tasks/{id}/cancel実行中のタスクの停止または待機中のタスクのキャンセル（技術者）
GET /api/v1/alerts?state=open未解決のアラート（state=all で解決済みも含む）
GET /api/v1/softwareソフトウェア ライブラリのパッケージ（技術者）
POST /api/v1/software/{id}/installライブラリのパッケージをジョブとしてデバイスにインストール（技術者）
GET /api/v1/jobs/{id}ジョブのデバイスごとの結果（技術者）
GET /api/v1/policiesポリシーとその割り当て（管理者）
POST /api/v1/policies/{id}/assignポリシーを customer:ID、site:ID、device:ID に割り当て（管理者）
POST /api/v1/policies/unassign顧客、サイト、デバイスのポリシーを削除（管理者）
PUT /api/v1/devices/{id}/fieldsデバイスのカスタム フィールドを名前で設定し (JSON オブジェクト。空の値で削除)、その内容を返します。応答内のデバイスには custom_fields としてフィールドが含まれます

タスク

タスクはデバイスがオンラインになるまで待機し、コンソールの操作と同じようにデバイスの以前のタスクの後に実行されます。デバイスのアクティビティに表示されます。応答はタスクを含む 202 です。ステータスが done、failed、cancelled、expired のいずれかになるまで GET /api/v1/tasks/{id} で追跡します。種類とフィールド:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

例

デバイス 9 で PowerShell スクリプトを実行し、その結果を取得します:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

エラー

エラーは HTTP ステータスとともに JSON {"error": "…"} で返されます。400 は不正な要求、401 はトークンがない・誤っている・期限切れ、403 はトークンのロールで呼び出しが許可されていない、404 は存在しないかトークンで参照できない、409 はタスクがすでに終了している、429 はそのアドレスからのサインイン失敗が多すぎる場合です。API による変更はすべて、トークン名とともに監査ログに記録されます。

Windows 更新とソフトウェア

ControlZit は各コンピューターに不足している更新を表示し、手動またはスケジュールでインストールします。プログラムは winget でインストール・更新します。

概要

更新には、更新が不足しているデバイス（セキュリティ更新は別に集計）、再起動待ちのデバイス、最終インストール、最終検索が表示されます。エージェントは起動の数分後と、その後 1 日 2 回、不足している更新を検索します。今すぐ検索で即座に検索を開始します。

デバイスで

デバイスの更新タブには、不足している更新がカテゴリと重要度付きで、最近インストールした更新とともに表示されます。更新を選んで選択した更新をインストールをクリックすると、完了時にページに結果が表示されます。再起動が必要な場合はデバイスに表示され、デバイスページから再起動できます。

Defender の定義（Security Intelligence Update）は 1 日に数回公開され、そのたびに新しい更新 ID が付きます。インストールすると、エージェントはまず再検索し、その時点で Windows Update が提供している定義のバージョンをインストールします。

自動インストール

設定 → Windows 更新で、サーバーが自動でインストールする内容を選びます:

  • オフ — 更新はコンソールからのみインストールされます。
  • セキュリティ更新と重要な更新、Defender の定義。
  • 機能更新プログラムを除くすべての更新 — Windows の新しいバージョンが自動でインストールされることはありません。

曜日と時刻（サーバー時刻）を選びます。その時間にオンラインのデバイスはその日に 1 回インストールし、オフラインのデバイスは次の予定日まで待ちます。任意で、更新に再起動が必要なときは、サインイン中のユーザーへの通知から 5 分後にコンピューターが自動で再起動します。

更新が予期しない時刻に届かないよう、エージェントはポリシーで Windows Update の自動インストールをオフにします。エージェントを削除すると以前の設定に戻ります。

Linux

Linux では、エージェントが apt（Debian、Ubuntu。セキュリティ更新は -security ソースから）または dnf（RHEL 系。セキュリティ更新は更新情報から）で利用可能なパッケージ更新を読み取り、選択したパッケージをインストールします。自動インストールは Linux デバイスにも適用され、そこでの「セキュリティ更新」はセキュリティソースのパッケージです。

プログラム（winget）

Windows デバイスのプログラムタブは 3 つの部分に分かれています。利用可能な更新には winget が更新できるプログラムが表示され、すべて更新で更新するか、個別に更新できます。インストール済みには、Windows のインストール済みプログラム一覧にあるすべてのプログラム（コンピューター全体とサインイン中のユーザー）が表示され、名前または発行元で絞り込めます。アンインストールはプログラムをサイレントで削除します。Windows インストーラー（MSI）パッケージは msiexec /x、Inno Setup と NSIS のアンインストーラーはそのサイレントオプション、またはプログラム独自のサイレントコマンドを使います。結果はプログラムが実際に削除されたときにのみ報告されます。サイレントアンインストーラーのないプログラムには印が付き、コンピューター上またはスクリプトで削除する必要があります。プログラムのインストールは winget コミュニティリポジトリを検索し（例: 7-Zip、Chrome）、すべてのユーザー向けにサイレントでインストールします。インストールと更新には、現在の Windows 10 と 11 に付属する winget（App Installer）が必要です。

ソフトウェア → 公開ソースで、2 つ目の公開ソースとして Chocolatey を追加できます。追加すると、プログラムのインストールでソース（winget または Chocolatey）を選べるようになり、利用可能な更新には Chocolatey でインストールした新しいバージョンのあるプログラムも表示されます。Chocolatey クライアントは、デバイスで初めて必要になったときに winget でインストールされます。Chocolatey のパッケージはコミュニティが管理しており、通常はメーカーのサイトからプログラムをダウンロードします。

ソフトウェア ライブラリ

管理者はソフトウェアで独自のインストーラーをアップロードします。Windows インストーラー パッケージ（.msi）またはセットアップ プログラム（.exe）で最大 2 GB、名前、バージョン、サイレント インストール用の引数、成功を示す終了コード（既定は 0、1641、3010。後の 2 つは再起動でインストールが完了することを示します）を指定します。MSI の場合、エージェントはログ付きで msiexec /i を実行し、既定の引数は /qn /norestart です。EXE には独自のサイレント スイッチが必要です（例: /S（NSIS）、/VERYSILENT /NORESTART（Inno Setup）、/quiet）。

デバイスにインストールでは顧客、サイト、または個々の Windows デバイスを選び、ライブラリのスクリプトと同様にジョブを開始します。オンラインのデバイスはすぐに、オフラインのデバイスは 24 時間以内に接続したときにインストールします。エージェントはサーバーのエージェント ポートからインストーラーをダウンロードし、署名されたコマンドの SHA-256 と照合してから SYSTEM として実行します。ジョブ ページには各デバイスの結果が表示され、Windows インストーラー パッケージのログも結果とともに保存されます。技術者は担当顧客のデバイスにパッケージをインストールでき、デバイスのプログラム タブのプログラムのインストールからも行えます。

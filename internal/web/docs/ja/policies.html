ポリシー

ポリシーは、割り当てた顧客、サイト、デバイスの Windows Update、必須ソフトウェア、アラート ルール、自動化を設定し、オフィスや顧客のすべてのコンピューターを同じように管理できるようにします。

ポリシーの構成

  • Windows Update — 自動的にインストールするもの、曜日と時刻、更新に必要な場合にコンピューターを再起動するかどうか。
  • 必須ソフトウェア — ポリシーのすべての Windows デバイスに必要なプログラム。不足しているものはサーバーがインストールします。
  • アラート ルール — CPU、メモリ、ディスク、オフラインのデバイス、保留中の再起動、Defender とファイアウォールのしきい値、および実行されている必要があるサービス。
  • 自動化 — ポリシーのデバイスで、決まった曜日と時刻に実行されるライブラリのスクリプト。
  • BitLocker — システム ドライブの暗号化。回復キーはサーバーに保管されます。
  • ネットワーク チェック — デバイスが自身のネットワークから毎分チェックするアドレス (ping、TCP ポート、Web アドレス)。
  • プログラムの更新 — winget または Chocolatey が認識するインストール済みプログラムを、指定した曜日またはメンテナンス時間帯に更新します。
  • メンテナンス時間帯 — デバイスが作業してよい時間帯: インストール、強制再起動、必要に応じて新しいアラートの抑止。

各部分はポリシー内でオン/オフを切り替えます。オフの部分はこのポリシーでは設定されず、より具体性の低いポリシーまたは組み込みの既定値 (自動更新なし、標準のアラート ルール) から適用されます。

ポリシーの割り当て

ポリシーはポリシーで作成します。ポリシーのページの割り当て先で顧客、サイト、または個々のデバイスに割り当てます。デバイスのポリシー タブでは、そのデバイス自身のポリシーを設定します。顧客、サイト、デバイスにはポリシーを 1 つだけ割り当てられ、別のものを割り当てると置き換わります。

各部分には、それを設定している最も具体的な割り当てが適用されます。デバイスのポリシー、次にサイト、次に顧客、最後に組み込みの既定値です。例: 顧客のポリシーで Windows Update と必須ソフトウェアを設定し、あるサイトのポリシーでより厳しいアラート ルールだけを設定すると、そのサイトのデバイスには顧客の更新とソフトウェア、サイトのアラート ルールが適用されます。

ポリシーは1 つの顧客またはサーバー全体に属し、作成時に選択します。技術者は担当顧客のポリシーを作成・変更し、その顧客とそのサイト、デバイスに割り当てます。管理者はすべてのポリシーを管理でき、サーバー全体のポリシーの作成と BitLocker 部分の設定は管理者だけが行えます。顧客のポリシーをその顧客以外に割り当てることはできません。

新しい顧客にはそれぞれ、その顧客に割り当てられた独自のポリシー Default が、組み込みの Windows Update とアラートの設定で作成されます。これを変更するか、サイトやデバイスに独自のポリシーを割り当ててください。バージョン 0.6.3 へのアップグレード時に、ポリシーのない既存の顧客には、サーバーの以前の Windows Update とアラートの設定 (現在は設定画面にありません) を持つ Default ポリシーが作成されました。

必須ソフトウェア

各必須プログラムには、ソース（ソフトウェア ライブラリ、winget、Chocolatey）と、Windows のインストール済みプログラム一覧での名前に含まれる文字（例: 7-Zip）を指定します。サーバーは数分ごとに、オンラインの各 Windows デバイスのインベントリと必須プログラムを比較し、不足しているプログラムをタスクとしてインストールします。タスクはデバイスのアクティビティに表示されます。インストール後、デバイスは新しいインベントリを送信します。それでも不足している場合、サーバーは 6 時間後に再試行します。デバイスが最初のインベントリを送信するまでは何もインストールしません。

アラート ルール

ポリシーのしきい値はそのデバイスに適用されます。アラート メールとチャット チャネルは監視とアラートでサーバー全体に設定します。

自動化

自動化は、スクリプト ライブラリのスクリプトを選択した曜日と時刻（サーバー時刻）に、このポリシーから自動化が適用されるすべてのデバイスを対象とする 1 つのジョブとして実行します。オフラインのデバイスは 24 時間以内に接続したときに実行します。結果はジョブのページと各デバイスのアクティビティに表示されます。

BitLocker と回復キー

サーバーは Windows デバイスの BitLocker 回復キーを保管します。BitLocker が有効な各デバイスから 1 日 1 回読み取り、デバイスの BitLocker ページ（デバイス概要の BitLocker 行からリンク）の今すぐ回復キーを読み取るですぐに読み取ることもできます。キーはサーバーの秘密鍵で暗号化して保存されます。キーを表示できるのは、パスワードを入力した管理者だけです。表示されたキーと誤ったパスワードはすべて監査ログに記録されます。

システム ドライブで BitLocker を必須にするを設定したポリシーは、システム ドライブが暗号化されていない Windows デバイスで BitLocker をオンにします。エージェントはまず TPM を確認して回復キーを追加し、サーバーがキーを保存してから暗号化を開始します（TPM 保護機能、XTS-AES 256、使用領域のみ）。暗号化はコンピューターの使用中にバックグラウンドで行われます。TPM の準備ができていないデバイスや、BitLocker のない Windows エディション（Home）では理由がアクティビティに表示され、サーバーは 6 時間後に再試行します。管理者は、デバイスの BitLocker ページから個別にオンにすることもできます。

プログラムの更新

プログラムの更新部分は、新しいバージョンがあるインストール済みプログラムを更新します。対象は winget が認識するプログラムと、選択した場合は Chocolatey でインストールしたプログラムです。選んだ各曜日の選んだ時刻、またはメンテナンス時間帯に 1 回実行されます。更新しないリストのプログラム (パッケージ ID または名前の一部) は変更されません。更新リングの遅延を設定すると、新しいバージョンはサーバーが最初に検出してからその日数だけ待機します。各実行はデバイスのアクティビティに表示されます。

メンテナンス時間帯

メンテナンス時間帯は毎週の時間帯で、たとえば土曜日の 22:00 から 4 時間 (サーバー時刻) です。メンテナンス時間帯に設定した Windows 更新とプログラムの更新はこの時間に実行され、期限を過ぎた再起動は次の時間帯を待ちます。メンテナンス時間帯には新しいアラートを出さないをオンにすると、時間帯の間はデバイスが新しいアラートを開きません。すでに開いているアラートはそのままです。

デバイスに適用される設定

デバイスのポリシー タブには、各部分を設定しているポリシー (デバイス、サイト、顧客のどれに割り当てられているか) または組み込みの既定値が適用されていること、各必須プログラムの状態 (インストール済み、不足、インストール開始日時)、適用されている Windows Update とアラートの設定、自動化が表示されます。

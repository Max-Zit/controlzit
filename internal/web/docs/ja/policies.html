ポリシー

ポリシーは、割り当てた顧客、サイト、デバイスの Windows Update、必須ソフトウェア、アラート ルール、自動化を設定し、オフィスや顧客のすべてのコンピューターを同じように管理できるようにします。

ポリシーの構成

  • Windows Update — 自動的にインストールするもの、曜日と時刻、更新に必要な場合にコンピューターを再起動するかどうか。
  • 必須ソフトウェア — ポリシーのすべての Windows デバイスに必要なプログラム。不足しているものはサーバーがインストールします。
  • アラート ルール — CPU、メモリ、ディスク、オフラインのデバイス、保留中の再起動、Defender とファイアウォールのしきい値、および実行されている必要があるサービス。
  • 自動化 — ポリシーのデバイスで、決まった曜日と時刻に実行されるライブラリのスクリプト。

各部分はポリシー内でオン・オフを切り替えます。オフの部分はこのポリシーでは設定されず、より具体的でないポリシーかサーバー自身の設定（Windows 更新、監視とアラート）から適用されます。

ポリシーの割り当て

ポリシーはポリシーで作成します（管理者）。ポリシーのページの割り当て先で顧客、サイト、または個々のデバイスに割り当てます。デバイスのポリシー タブでは、そのデバイス自身のポリシーを設定します。顧客、サイト、デバイスにはポリシーを 1 つだけ割り当てられ、別のものを割り当てると置き換わります。

各部分には、それを設定している最も具体的な割り当てが適用されます。デバイスのポリシー、次にサイト、次に顧客、最後にサーバーの設定です。例: 顧客のポリシーが Windows Update と必須ソフトウェアを設定し、あるサイトのポリシーがより厳しいアラート ルールだけを設定している場合、そのサイトのデバイスには顧客の更新とソフトウェア、サイトのアラート ルールが適用されます。

必須ソフトウェア

各必須プログラムには、ソース（ソフトウェア ライブラリ、winget、Chocolatey）と、Windows のインストール済みプログラム一覧での名前に含まれる文字（例: 7-Zip）を指定します。サーバーは数分ごとに、オンラインの各 Windows デバイスのインベントリと必須プログラムを比較し、不足しているプログラムをタスクとしてインストールします。タスクはデバイスのアクティビティに表示されます。インストール後、デバイスは新しいインベントリを送信します。それでも不足している場合、サーバーは 6 時間後に再試行します。デバイスが最初のインベントリを送信するまでは何もインストールしません。

アラート ルール

ポリシーのしきい値は、そのデバイスについてサーバーのしきい値を置き換えます。アラートのメールとチャット チャネルは、監視とアラートのものがそのまま使われます。

自動化

自動化は、スクリプト ライブラリのスクリプトを選択した曜日と時刻（サーバー時刻）に、このポリシーから自動化が適用されるすべてのデバイスを対象とする 1 つのジョブとして実行します。オフラインのデバイスは 24 時間以内に接続したときに実行します。結果はジョブのページと各デバイスのアクティビティに表示されます。

デバイスに適用される設定

デバイスのポリシー タブには、各部分をどのポリシーが設定しているか（デバイス、サイト、顧客のどれに割り当てられているか）またはサーバーの設定が適用されていること、各必須プログラムの状態（インストール済み、不足、インストールを開始した時刻）、適用されている Windows Update とアラートの設定、および自動化が表示されます。

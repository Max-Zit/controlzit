監視、アラート、通知

サーバーは各デバイスを 1 分ごとに確認します。アラートは条件が続く間は開いたままで、条件がなくなると自動的に閉じます。通知はメール、チャットチャネル、Webhook で届きます。

アラートルール

ルールは顧客、サイト、デバイスのポリシーで設定します (各顧客には独自のポリシー Default があります)。アラート メール、メール サーバー、チャット チャネルは設定 → 監視とアラートにあります。

ルール発生する条件
CPU 負荷負荷が選んだ分数のあいだ上限を超え続けた
メモリ使用率メモリ使用率が選んだ分数のあいだ上限を超え続けた
ディスク容量ディスクの使用率が割合を超えた、または（その 2 倍より大きいディスクで）空き容量が指定 GB を下回った
デバイスがオフラインエージェントが指定した分数より長く接続していない
再起動待ち再起動待ちで、指定した日数より長く稼働している
Microsoft Defender がオフウイルス対策またはリアルタイム保護がオフ（任意）
ファイアウォールがオフWindows ファイアウォールのプロファイルがオフ（任意）
サービスが停止一覧のサービス（表示名ではなくサービス名）が自動開始に設定されているのに実行されていない
ディスクがまもなく満杯過去 14 日間の使用領域の増加から、ディスクが指定した日数以内に満杯になる（0 = オフ）

アラートは警告または重大です（重大: オフラインのデバイス、停止したサービス、Defender がオフ、空きが 1 GB 未満または使用率 98 % のディスク）。アラートには未解決のアラート（必要なら解決済みも）が表示されます。技術者はアラートを確認済みにすることで、誰かが対応中であることを他の人に示せます。未解決のアラート数はメニューに表示されます。

ネットワーク チェック

ポリシーのネットワーク チェック部分には、ポリシーの各デバイスが自身のネットワークから毎分チェックするアドレスを指定します: ping (ルーター、プリンター、サーバー)、TCP ポート (たとえば 1433 のデータベース)、または HTTP エラーなしで有効な証明書を使って応答する必要がある Web アドレスです。チェックが指定した分数より長く失敗したとき、および Web アドレスの証明書の期限切れ 14 日前にアラートが開きます。デバイスの概要には各チェックと応答時間が表示されます。

ディスクの状態

デバイスは 1 時間ごとに物理ディスクの状態を報告します。Windows ではディスクが Windows に報告する情報 (SMART: 状態、温度、SSD の消耗、訂正されていないエラー) と記憶域スペースのディスク、Linux では smartctl (smartmontools パッケージ) による SMART と md ソフトウェア RAID アレイです。問題を報告したディスクと劣化した RAID アレイは、ポリシーのアラート ルールでオフにしていない限りアラートを開きます。ハードウェア RAID コントローラーの背後にあるディスクはシステムから見えないため対象外です。デバイスの概要にディスクが表示されます。

アラートメール

  1. メールサーバー（SMTP）を入力します: ホスト、ポート、接続のセキュリティ（STARTTLS または TLS。パスワードが暗号化されていない接続で送られることはありません）、ユーザー、パスワード、送信者。パスワードは暗号化して保存されます。
  2. 受信者を 1 行に 1 アドレスで追加し、アラート解決時にもメールを送るかどうかを選びます。
  3. テストメールを送信をクリックします。

Slack、Microsoft Teams、Webhook

チャットと Webhook で最大 20 チャネルを追加できます:

  • Slack — チャネルの受信 Webhook の URL。
  • Microsoft Teams — チャネルのワークフロー「Teams Webhook 要求を受信したとき」とその URL。
  • Webhook — JSON の POST を受け付ける任意の HTTPS URL（チケットシステム、自動化）。シークレットを設定すると、各要求に X-ControlZit-Signature: sha256=<本文の HMAC> が付き、受信側はサーバーから送られたことを確認できます。

チャネルごとにすべてのアラートか重大なアラートのみか、解決済みも送るかを選びます。テストを送信でテストメッセージを送ります。チャネルのアドレスは暗号化して保存されます。

現在の値

デバイスのページには、現在の CPU 負荷、メモリとディスク、実行されていない自動開始サービスが表示されます。

履歴とディスクの予測

デバイスの History タブには、CPU 負荷、メモリ、ネットワーク通信量（エージェント 0.11 以降）、各ディスクの使用領域が 24 時間・7 日・30 日・90 日の範囲で描かれます。1 分ごとの値は 7 日間、1 時間ごとの集計は 90 日間保存されます。

サーバーは 1 時間ごとのディスク容量から、過去 14 日間と同じペースで増え続けた場合に各ディスクがいつ満杯になるかを計算します。90 日以内に満杯になるディスクはデバイスページに表示され、警告ルール ディスクがまもなく満杯 はポリシーで設定した日数以内でアラートを開きます（新しいポリシーでは 14 日、3 日以内は重大）。

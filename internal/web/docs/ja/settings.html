サーバーの設定と更新

管理者は設定でサーバーの設定を行います: ネットワークとポート、証明書、タイムゾーン、サーバーとエージェントの更新、サポート用の診断情報。

ネットワークとアクセス

設定 → ネットワークとアクセス:

  • コンソール — 待ち受けアドレスとポート（既定 :8443）と許可するネットワーク（1 行に 1 つの IP アドレスまたはネットワーク、CIDR）。他のアドレスからの接続は TLS の前に切断されます。サーバー自身（127.0.0.1）は常に許可されます。自分のアドレスを締め出す一覧は保存できません。
  • エージェントのエンドポイント — 待ち受けアドレスとポート（既定 :8444、コンソールとは別のポート）、エージェントの接続元として許可するネットワーク（空欄 = すべて）、インストーラーと登録コードに書き込まれるエージェント用の公開アドレス。
  • 新しいポートは今すぐ再起動（RMMZit サービスを再起動。エージェントは自動で再接続）の後に有効になります。

締め出された場合は、サーバーで rmmzit-server --reset-allowlist を実行します（アプライアンス: セットアップメニューの項目 5）。

サーバーのネットワーク（アプライアンス）

RMMZit アプライアンスでは、サーバー自体のネットワークもここで設定します: DHCP またはネットワークサイズ付きの固定アドレス（例: 192.168.1.20/24）、ゲートウェイ、1～3 個の DNS サーバー、サーバー名。新しい設定でゲートウェイが応答しない場合、30 秒後に以前の設定に自動で戻ります。他のインストールではネットワークは OS が管理します。

タイムゾーン

スケジュール（更新、スクリプト、レポート）とコンソールの時刻は、サーバーのタイムゾーンを使用します。一覧から選んで設定をクリックすると、コンソールが再起動し数秒で戻ります。root ヘルパーがない場合（下記参照）は、サーバーで設定します: timedatectl set-timezone Asia/Tokyo。

証明書（HTTPS）

設定 → 証明書で、ブラウザーがコンソールを開いたときに表示される証明書を選びます。エージェントは独自のポートと証明書を使うため、変更しても接続が切れることはありません。

  • コンソール自身の証明書（自己署名）— すぐに使えますが、ブラウザーが警告します。
  • Let's Encrypt — 有効期限の 30 日前に自動更新される無料の証明書。コンソールの公開 DNS 名とメールアドレスを入力し、確認方法を選びます:
    • ポート 80 — 名前がこのサーバーを指し、ポート 80 にインターネットから到達できる場合。サーバーがポート 80 で応答し、ブラウザーを HTTPS へ転送します。
    • Cloudflare DNS — インターネットから到達できないサーバー向け。ゾーンの Zone:DNS:Edit 権限を持つ Cloudflare API トークンが必要です。
  • 証明書をアップロード — 認証局または社内 CA の証明書（PEM、中間証明書を含む）と秘密鍵。鍵はこのサーバーにのみ保存されます。

サーバーの更新

設定 → RMMZit の更新には、実行中のバージョンと最新リリースが表示されます。インストールでサーバーを更新します。RMMZit のリリース鍵で署名されたリリースのみがインストールされ、インストール前にサーバーはデータベースとプログラムをバックアップし、新しいバージョンが起動しない場合は自動で元に戻ります。コンソールは 1～2 分使えなくなります。任意で、選んだ時間帯に新しいバージョンを自動インストールできます。

更新チャネル: 公式リリース (既定) または テスト。テストではリリース候補が公式になる前にテスト用コンソールへ提供されます。本番のコンソールは公式リリースのままにしてください。

更新、タイムゾーン、ネットワークには、Linux パッケージとアプライアンスに含まれる root ヘルパーが必要です。ない場合（プログラム単体など）は、install.sh またはリリースのパッケージで更新してください。

エージェントの更新

エージェントのインストール → エージェントの更新を参照してください。

診断

設定 → 診断には、RMMZit のログの書き込み先、サーバーログの最新行（レベルやテキストで絞り込み）、root ヘルパーのログ、バージョンが表示されます。診断情報をダウンロード（ZIP）は、ログ、バージョンと設定の概要、デバイス、アラート、監査ログを含むサポート用ファイルを作成します。表示されるすべての内容とファイルから、パスワード、トークン、登録コード、鍵は削除されます。スクリプトとその出力は含まれません。

カスタム フィールド

設定 → カスタム フィールドで、管理者はデバイスと顧客の独自フィールド (テキスト、数値、日付) を追加します。たとえば資産番号、保証終了日、契約などです。技術者がデバイスと顧客のページで入力し、API は各デバイスとともにフィールドを返し、PUT /api/v1/devices/{id}/fields で設定します。

コンソールのバックアップ

設定 → コンソールのバックアップ は、毎日指定した時刻に、または 今すぐバックアップ ですぐにコンソールをバックアップします。バックアップには、データベース、保存されたパスワードの秘密鍵、エージェントが信頼する証明書と鍵、ソフトウェアライブラリが含まれます。最新のバックアップ（指定した数）はデータディレクトリの backups フォルダーに残り、ページからダウンロードできます。

パスフレーズを設定するとファイルは暗号化されます（AES-256-GCM）。パスフレーズがないとバックアップを復元できないため、別の場所に保管してください。各バックアップのコピーを別のサーバーの SFTP フォルダーに送ることもできます（パスワードまたは秘密鍵）。接続の最初のテストで信頼するサーバーのホスト鍵が表示され、コピーはその鍵を持つサーバーにのみ送られます。バックアップまたはそのコピーに失敗すると、アラートメールの宛先にメールが届きます。

復元はサーバーを停止した状態で実行します。アプライアンスではセットアップメニュー（Restore a backup）、Linux パッケージでは次のとおりです:

sudo systemctl stop rmmzit-server
sudo -u rmmzit sh -c 'set -a; . /etc/rmmzit/server.env; rmmzit-server -data-dir /var/lib/rmmzit -restore /path/rmmzit-backup-….czb'
sudo systemctl start rmmzit-server

暗号化されたバックアップのパスフレーズは RMMZIT_BACKUP_PASSPHRASE または -restore-passphrase-file で指定したファイルから読み取られます。データベースは 1 回の処理で復元されます（失敗した場合は何も変わりません）。より新しい RMMZit は起動時に復元したデータベースを更新します。バックアップから復元した新しいサーバーは、同じ証明書を信頼するためすべてのエージェントをそのまま引き継ぎます。

セキュリティ

RMM サーバーは管理するすべてのコンピューターを制御できます。RMMZit は、攻撃者がコンソール、ネットワーク、さらにはサーバーに到達しても得られるものが最小限になるように作られています。

RMMZit による保護

  • 2 つのポート。コンソールとエージェントのエンドポイントは別々のポートで待ち受けます。コンソールは許可されたネットワークからの接続のみを TLS の前に確認して受け付けるため、エージェントのポートを公開してもコンソールは露出しません。
  • 送信接続のエージェント。エージェントがサーバーへ接続するため、管理対象コンピューターでポートを開く必要はありません。エージェントはサーバー証明書をフィンガープリントで固定するので、偽のサーバーに乗っ取られません。
  • 署名付きコマンド。エージェントへのすべてのコマンドはサーバーのコマンド鍵で署名され、エージェントが検証します。エージェントの更新は署名付きコマンドの SHA-256 と一致する必要があります。
  • 強固なサインイン。すべてのローカルアカウントとディレクトリアカウントで 2 段階サインイン、argon2id のパスワード、短いセッション、無操作後のサインアウト、失敗したサインインの段階的なブロック。
  • ブラウザーの保護。すべての変更での CSRF チェック、インラインスクリプトを禁止する厳格な Content Security Policy、__Host- セッション Cookie。
  • 最小権限。ロールと顧客単位のアクセス。コンソールは特権のないユーザーで動作し、わずかな root 操作（更新、ネットワーク、タイムゾーン）は、決められた検証済みの要求だけを受け付ける別の root ヘルパーを経由します。
  • 監査。すべての変更とリモート操作を記録する、ハッシュで連結された監査ログ。
  • 署名付きリリース。サーバー、エージェント、install.sh は RMMZit のリリース鍵で署名されたリリースのみをインストールします。
  • シークレット。保存されたパスワード（メール、LDAP、チャネル、Cloudflare）はサーバーの秘密鍵で暗号化され、診断情報からはシークレットが削除されます。

ベストプラクティス

  1. コンソールには管理用ネットワークからのみアクセスできるようにし、外部からのアクセスにはコンソールのポートを開く代わりに VPN（例: WireGuard）を使います。
  2. エージェントのポートはエージェントがある場所だけで開き、すべてのエージェントが既知のアドレスから接続する場合はエージェントのネットワークを設定します。
  3. ユーザーが警告を無視する癖をつけないよう、ブラウザーが信頼する証明書（Let's Encrypt または自社 CA）を使います。
  4. 各自に最小のロールと必要な顧客だけを持つ専用アカウントを与え、退職者のアカウントは無効にします。
  5. 緊急用にローカル管理者を 1 人残し、その回復コードはオフラインで保管します。
  6. RMMZit の更新は速やかにインストール（または自動更新をオン）し、サーバーの OS を最新に保ちます。アプライアンスは Debian のセキュリティ更新を自動でインストールします。
  7. データベースと /var/lib/rmmzit を定期的にバックアップし、サーバーから離れた場所に保管します。
  8. ときどき監査ログを確認し、誰かが接続しているときにユーザーがわかるよう、リモート画面の通知はオンのままにします。

脆弱性の報告

セキュリティの問題は公開の issue ではなく、GitHub → Security → Report a vulnerability から非公開で報告してください。

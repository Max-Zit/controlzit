ユーザー、ロール、サインイン

各自が自分のアカウントでサインインします。ロールで操作できる範囲が、顧客へのアクセスで閲覧できる範囲が決まり、すべての操作は本人の名前で監査ログに記録されます。

ロール

ロールできること
管理者ユーザーと設定を含むすべて。常にすべての顧客を表示
技術者許可された顧客のデバイスを管理: リモートアクセス、スクリプト、更新、プログラム、アラート
読み取り専用許可された顧客の閲覧のみ: デバイス、アラート、更新、レポート

技術者と読み取り専用ユーザーには、すべての顧客（今後の顧客を含む）または一部の顧客のみへのアクセスを与えます。

ローカルアカウント

ユーザーで、管理者が初期パスワード付きでユーザーを追加します。ユーザーは初回サインイン時にパスワードを変更し、2 段階サインインを設定する必要があります。管理者はユーザーを無効化（開いているセッションは終了）したり、新しいパスワードを設定したり、電話と回復コードを紛失したユーザーの 2 段階サインインをリセットしたりできます。有効な管理者が常に少なくとも 1 人残ります。

2 段階サインイン

RMMZit はすべての管理対象コンピューターに管理者権限でアクセスできるため、すべてのローカルアカウントとディレクトリアカウントに認証アプリ（Microsoft Authenticator、Google Authenticator、Authy、1Password、Bitwarden …）が必要です。各アカウントには 10 個の使い捨て回復コードも発行され、新しいコードはアカウントで作成できます。サインインに失敗するとアドレスが一定時間ブロックされます（繰り返すほど長くなります）。制限は、セッションの長さや無操作後のサインアウトとともに設定 → サインインとセキュリティにあります。

Active Directory / LDAP

設定 → Active Directory / LDAP で、ユーザーはディレクトリのアカウントでサインインします。パスワードはディレクトリが確認し、RMMZit は独自の 2 つ目の要素も求めます。

  • サーバー: ldaps://dc1.example.local（ポート 636）、または StartTLS を使う ldap://（389）。パスワードが暗号化されずにネットワークを流れることはありません。ディレクトリの証明書が社内 CA 発行の場合は CA 証明書を追加します。
  • サービスアカウント（DN または user@domain）とそのパスワード、ベース DN、ユーザーフィルター（Active Directory の例: (&(objectClass=user)(sAMAccountName={username}))）。
  • グループとロール: ディレクトリのグループを管理者、技術者、読み取り専用に割り当てます。最も高いロールが優先されます。Active Directory の入れ子のグループも含められます。
  • 顧客グループ: グループ = 顧客 の行で、技術者と読み取り専用ユーザーをその顧客に限定します。

テストは、保存した設定でディレクトリのアカウントをサインインせずに確認し、RMMZit がどう扱うかを表示します。ディレクトリのアカウントは RMMZit ではなくディレクトリでパスワードを変更します。

シングルサインオン（OpenID Connect、SAML）

設定 → シングルサインオンで、ユーザーは ID プロバイダーのアカウントでサインインします: OpenID Connect（Microsoft Entra ID、Google、Okta、Keycloak …）または SAML 2.0（ADFS、Entra ID、Okta …）。サインインページにボタンが表示されます。

  • OpenID Connect: ページに表示されるリダイレクト URI でプロバイダーにアプリケーションを登録し、発行者（例: https://login.microsoftonline.com/<tenant>/v2.0）、クライアント ID、クライアントシークレットを入力します。
  • SAML: コンソールのメタデータ（ページのリンク）またはエンティティ ID と応答（ACS）アドレスをプロバイダーに渡し、プロバイダーのメタデータ URL を入力するか XML を貼り付けます。
  • グループのクレームでグループ（名前または ID。Entra ID はグループ ID を送信）を受け取り、LDAP と同様にロールと顧客に割り当てます。
  • ID プロバイダーの多要素認証ポリシーが適用されます。任意で RMMZit 独自の 2 つ目の要素も求めます。

LDAP やシングルサインオンを有効にしてもローカルアカウントは使えるため、管理者はいつでもサインインできます。緊急用にローカル管理者を 1 人残しておいてください。

監査ログ

監査ログには、すべての変更とリモート操作が、ユーザー、対象（顧客、拠点、デバイス、ユーザー。リンク付き）、アドレスとともに表示されます。エントリはハッシュで連結されており、コンソールは表示のたびにチェーンを確認し、エントリが変更・削除された場合は報告します。

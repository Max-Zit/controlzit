API

L'API REST permette a script e altri strumenti di leggere dispositivi, avvisi e attività e di avviare lavori sui dispositivi, con gli stessi diritti della console.

Token

Crea un token in Il mio account → Token API: un nome, un ruolo non superiore al tuo (sola lettura, tecnico o amministratore) e la durata della validità. Il token viene mostrato una sola volta; conservalo come una password. Agisce come te, con i tuoi clienti. Invialo in ogni richiesta come Authorization: Bearer czt_… all'indirizzo della console (porta 8443), che accetta connessioni solo dalle reti consentite. I cookie di sessione del browser non funzionano con l'API. Eliminare il token nella pagina dell'account ne termina subito l'accesso.

Attività

Un'attività attende che il dispositivo sia online e viene eseguita dopo le attività precedenti del dispositivo, come le azioni nella console; compare nelle Attività del dispositivo. La risposta è 202 con l'attività; seguila con GET /api/v1/tasks/{id} finché lo stato non è done, failed, cancelled o expired. I tipi e i loro campi:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Esempi

Uno script PowerShell sul dispositivo 9, poi il suo risultato:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Errori

Gli errori arrivano come JSON {"error": "…"} con lo stato HTTP: 400 per una richiesta errata, 401 per un token mancante, errato o scaduto, 403 quando il ruolo del token non consente la chiamata, 404 per qualcosa che non esiste o che il token non può vedere, 409 quando un'attività è già terminata, 429 dopo troppi accessi falliti dall'indirizzo. Ogni modifica tramite l'API viene registrata nel registro attività con il nome del token.

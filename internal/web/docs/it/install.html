Installare il server

Scegli uno dei cinque modi. L'immagine VM pronta è la più veloce; lo script di installazione è adatto a un server Linux esistente, Docker a un host Docker esistente.

ModoIdeale perRichiede
1. Immagine VM (OVA, qcow2, VHDX)importare, avviare, accedere, in pochi minutiVMware, Proxmox / KVM o Hyper-V
2. ISO dell'applianceuna nuova VM o un server fisico, senza interventiaccesso a Internet durante l'installazione

4. Pacchetti a manoPostgreSQL proprio, gestione della configurazione, server offlineil pacchetto deb o rpm di una release
5. Docker (immagine container)un host Docker esistente, un NAS o un home labDocker con il plugin Compose; accesso a Internet per scaricare l'immagine

Tutti i file sono nella pagina delle release. Dai al server 2 vCPU, 2–4 GB di RAM e un disco da almeno 16 GB.

1. Immagine VM

  1. Importa l'immagine:
    • VMware ESXi / Workstation, VirtualBox: distribuisci rmmzit-appliance.ova (Create / Register VM → Deploy a virtual machine from an OVF or OVA file).
    • Proxmox VE: crea una VM senza disco (2 vCPU, 2–4 GB di RAM, rete VirtIO), copia rmmzit-appliance.qcow2 sul nodo ed esegui qm importdisk <vmid> rmmzit-appliance.qcow2 local-lvm; collega il disco come SCSI e rendilo il disco di avvio.
    • Hyper-V: decomprimi rmmzit-appliance-vhdx.zip e crea una VM di generazione 1 con il VHDX come disco.
  2. Avvia la VM. Il disco si espande da solo alla dimensione del disco virtuale. Lo schermo della VM mostra l'indirizzo della console e il token di configurazione.
  3. Apri https://<indirizzo>:8443. Il browser avvisa una volta del certificato autofirmato (sostituiscilo poi in Impostazioni → Certificato). Inserisci il token e crea il primo amministratore.

L'appliance ottiene l'indirizzo tramite DHCP. Per un indirizzo fisso, il nome del server o il fuso orario, accedi sullo schermo della VM come rzadmin (prima password rmmzit, da cambiare): si apre un menu di configurazione. Fuso orario e rete si possono cambiare anche in seguito dalla console.

2. ISO dell'appliance

  1. Avvia una VM o un server da rmmzit-appliance.iso. Dopo 5 secondi l'installazione parte da sola: cancella il primo disco, installa Debian, PostgreSQL e RMMZit e richiede accesso a Internet (10–20 minuti).
  2. Dopo il riavvio lo schermo mostra l'indirizzo della console e il token di configurazione, come con l'immagine VM.

3. Script di installazione

Su un server Linux esistente, come root:

curl -fsSL https://github.com/Max-Zit/rmmzit/releases/latest/download/install.sh | sudo sh

Lo script installa PostgreSQL, scarica la release più recente, ne verifica la firma, crea un database con una password casuale e avvia il servizio. Opzioni (dopo sh -s --): --version X, --db postgres://… per un database esistente, --no-auto-updates per lasciare disattivati gli aggiornamenti di sicurezza automatici del sistema operativo. Rieseguirlo aggiorna RMMZit e conserva i dati.

4. Pacchetti a mano

sudo apt install ./rmmzit-server_X_amd64.deb      # Debian, Ubuntu
sudo dnf install ./rmmzit-server-X-1.x86_64.rpm     # AlmaLinux, Rocky Linux

Poi scrivi l'indirizzo del database in /etc/rmmzit/server.env (RMMZIT_DB=postgres://…) e avvia il servizio con systemctl enable --now rmmzit-server.

5. Docker

Il server è disponibile anche come immagine container, ghcr.io/max-zit/rmmzit, creata dallo stesso pacchetto server firmato degli altri modi; funziona con PostgreSQL tramite Docker Compose. Scarica docker-compose.yml e .env.example in una cartella, copia .env.example in .env, imposta una password del database (lettere e cifre) e il fuso orario, poi:

docker compose up -d
docker compose exec rmmzit rmmzit-server -setup-token

Apri https://<host>:8443 e inserisci il token di configurazione. La porta 8444 è l'endpoint degli agenti; aprila dove si connettono gli agenti. Il tag dell'immagine in .env decide cosa è in esecuzione: latest per le versioni ufficiali, testing per le release candidate.

Aggiorna con docker compose pull && docker compose up -d. Prima che una nuova versione modifichi il database, il server scrive un backup in Impostazioni → Backup della console. Per tornare indietro, imposta la versione precedente come tag dell'immagine e ripristina quel file: docker compose stop rmmzit, docker compose run --rm rmmzit -restore /var/lib/rmmzit/backups/FILE, docker compose up -d. In un container la rete e il fuso orario appartengono all'host Docker, non alla console.

Primo accesso

  • Il token di configurazione è in /var/lib/rmmzit/setup-token.txt e nel log del server (journalctl -u rmmzit-server). Vale una sola volta.
  • Ogni account richiede un'app di autenticazione (TOTP) e riceve 10 codici di recupero. Conservali al sicuro.
  • Per impostazione predefinita la console accetta connessioni solo dalle reti private. Se resti chiuso fuori, esegui rmmzit-server --reset-allowlist sul server (appliance: menu di configurazione, voce 5).

Dove si trova cosa

PercorsoCosa
/etc/rmmzit/server.envconfigurazione: database, porte, origine degli aggiornamenti (leggibile solo da root e dal servizio)
/var/lib/rmmzitdirectory dei dati: certificati, chiave segreta, installer degli agent (downloads), log
/var/lib/rmmzit/logs/server.loglog del server; anche in journalctl -u rmmzit-server
/var/log/rmmzit-helperlog dell'helper root (aggiornamenti, fuso orario, rete)

Esegui il backup del database insieme a /var/lib/rmmzit: la chiave segreta lì contenuta decifra le password salvate e i certificati identificano il server presso i suoi agent.

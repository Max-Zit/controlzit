Risoluzione dei problemi e FAQ

Le domande più comuni e cosa controllare per primo. Per una richiesta di assistenza, scarica la diagnostica in Impostazioni → Diagnostica.

Non riesco a raggiungere la console

  • Il tuo indirizzo potrebbe non essere nelle reti consentite: la connessione viene chiusa prima di TLS, quindi il browser mostra un errore di connessione. Esegui controlzit-server --reset-allowlist sul server (appliance: menu di configurazione, voce 5) per consentire di nuovo tutte le reti private.
  • Dopo aver cambiato la porta, apri la console sulla nuova porta.
  • Controlla il servizio sul server: systemctl status controlzit-server e journalctl -u controlzit-server.

Problemi di accesso

  • Il codice è errato — l'ora del telefono deve essere corretta (ora automatica).
  • Telefono perso — accedi con un codice di recupero; un altro amministratore può reimpostare l'accesso a due fattori.
  • Troppi tentativi falliti — l'indirizzo è bloccato per un po'; un amministratore può sbloccarlo in Impostazioni → Accesso e sicurezza. Gli accessi dal server stesso non vengono mai bloccati.
  • LDAP / Single Sign-On — usa Prova nella pagina LDAP; controlla i gruppi che il provider invia. Il log del server contiene i dettagli.

Un agent non si connette

  • Il computer raggiunge la porta degli agent? Su Windows: Test-NetConnection rmm.example.com -Port 8444.
  • L'indirizzo pubblico degli agent è corretto? I codici creati con la console aperta su localhost mandano l'agent al server sbagliato; imposta l'indirizzo e crea un nuovo codice.
  • Il codice è ancora valido e non esaurito?
  • Log dell'agent: Windows C:\ProgramData\ControlZit Agent\agent.log, Linux /var/lib/controlzit-agent/agent.log e journalctl -u controlzit-agent; per un dispositivo connesso aprili dalla console in File. Su Windows l'icona accanto all'orologio mostra lo stato della connessione.

Il desktop remoto non mostra nulla

  • Linux con Wayland non può essere mostrato: accedi con una sessione X11 (Xorg) o usa il terminale.
  • Linux senza desktop: usa il terminale.
  • Copiare file tramite gli appunti richiede un utente connesso sul computer Windows.

Gli aggiornamenti di Windows non vengono installati

  • Controlla l'installazione automatica in Impostazioni → Aggiornamenti di Windows: giorni, ora e modalità. I dispositivi devono essere online in quell'ora.
  • La scheda Aggiornamenti del dispositivo mostra l'ultima ricerca ed eventualmente il suo errore.

Le email di avviso non arrivano

Usa Invia un'email di prova in Impostazioni → Monitoraggio e avvisi; il messaggio mostra la risposta del server. Una password viene inviata solo tramite STARTTLS o TLS.

FAQ

ControlZit ha bisogno di un servizio cloud?

No. Tutto gira sul tuo server; nulla viene inviato a MaxZit. Il server controlla soltanto GitHub per le nuove release.

Come faccio il backup di ControlZit?

Esegui il backup del database PostgreSQL (pg_dump) e della cartella /var/lib/controlzit. Senza la chiave segreta e i certificati lì contenuti, le password salvate non possono essere decifrate e gli agent non si fiderebbero di un nuovo server.

Posso spostare il server su una nuova macchina?

Sì: installa ControlZit sulla nuova macchina, ripristina il database e /var/lib/controlzit e mantieni lo stesso indirizzo (oppure cambia l'indirizzo pubblico degli agent e fai puntare il vecchio nome alla nuova macchina).

Esiste un agent per macOS?

Non ancora. Sono supportati Windows e Linux (x86-64, ARM64).

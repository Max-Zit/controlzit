Sicurezza

Un server RMM può controllare ogni computer che gestisce. RMMZit è costruito in modo che un attaccante che raggiunge la console, la rete o persino il server ottenga il meno possibile.

Come ti protegge RMMZit

  • Due porte. La console e l'endpoint degli agent ascoltano su porte separate. La console accetta connessioni solo dalle reti consentite, verificate prima di TLS; la porta degli agent può essere pubblica senza esporre la console.
  • Agent in uscita. Gli agent si connettono al server; i computer gestiti non hanno bisogno di porte aperte. Gli agent fissano il certificato del server tramite la sua impronta, quindi un server falso non può prenderne il controllo.
  • Comandi firmati. Ogni comando a un agent è firmato con la chiave dei comandi del server e verificato dall'agent; gli aggiornamenti degli agent devono corrispondere allo SHA-256 di un comando firmato.
  • Accesso robusto. Due fattori per ogni account locale e di directory, password argon2id, sessioni brevi, disconnessione dopo inattività, blocco progressivo degli accessi falliti.
  • Protezioni del browser. Controlli CSRF a ogni modifica, una Content Security Policy rigorosa senza script inline, cookie di sessione __Host-.
  • Privilegio minimo. Ruoli e accesso per cliente; la console gira come utente non privilegiato, e le poche azioni root (aggiornamenti, rete, fuso orario) passano da un helper root separato che accetta solo richieste fisse e convalidate.
  • Audit. Un log di audit concatenato con hash di ogni modifica e ogni azione remota.
  • Release firmate. Server, agent e install.sh installano solo release firmate con la chiave di release di RMMZit.
  • Segreti. Le password salvate (email, LDAP, canali, Cloudflare) sono cifrate con la chiave segreta del server; la diagnostica rimuove i segreti.

Buone pratiche

  1. Rendi la console raggiungibile solo dalle tue reti di amministrazione; per l'accesso dall'esterno usa una VPN (ad esempio WireGuard) invece di aprire la porta della console.
  2. Apri la porta degli agent solo dove ci sono agent e imposta le reti degli agent se tutti provengono da indirizzi noti.
  3. Usa un certificato di cui i browser si fidano (Let's Encrypt o la tua CA), così gli utenti non si abituano a ignorare gli avvisi.
  4. Dai a ogni persona il proprio account con il ruolo minimo e solo i clienti necessari; disattiva gli account di chi se ne va.
  5. Tieni un amministratore locale per le emergenze, con i codici di recupero conservati offline.
  6. Installa presto gli aggiornamenti di RMMZit (o attiva quelli automatici) e mantieni aggiornato il sistema operativo del server; l'appliance installa da sola gli aggiornamenti di sicurezza di Debian.
  7. Esegui regolarmente il backup del database e di /var/lib/rmmzit e conservalo lontano dal server.
  8. Controlla di tanto in tanto il log di audit e lascia attivo l'avviso sullo schermo remoto, così gli utenti sanno quando qualcuno è connesso.

Segnalare una vulnerabilità

Segnala i problemi di sicurezza in privato tramite GitHub → Security → Report a vulnerability, non in una issue pubblica.

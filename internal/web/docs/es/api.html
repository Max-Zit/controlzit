API

La API REST permite a scripts y otras herramientas leer dispositivos, alertas y tareas e iniciar trabajo en los dispositivos, con los mismos derechos que en la consola.

Tokens

Cree un token en Mi cuenta → Tokens de API: un nombre, un rol no superior al suyo (solo lectura, técnico o administrador) y cuánto tiempo es válido. El token se muestra una sola vez; guárdelo como una contraseña. Actúa como usted, con sus clientes. Envíelo en cada solicitud como Authorization: Bearer czt_… a la dirección de la consola (puerto 8443), que solo acepta conexiones de las redes permitidas. Las cookies de sesión del navegador no funcionan en la API. Eliminar el token en la página de la cuenta termina su acceso al instante.

Tareas

Una tarea espera a que el dispositivo esté en línea y se ejecuta después de las tareas anteriores del dispositivo, igual que las acciones de la consola; aparece en la Actividad del dispositivo. La respuesta es 202 con la tarea; sígala con GET /api/v1/tasks/{id} hasta que su estado sea done, failed, cancelled o expired. Los tipos y sus campos:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Ejemplos

Un script de PowerShell en el dispositivo 9 y luego su resultado:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Errores

Los errores llegan como JSON {"error": "…"} con el estado HTTP: 400 para una solicitud incorrecta, 401 para un token ausente, erróneo o caducado, 403 cuando el rol del token no permite la llamada, 404 para algo que no existe o que el token no puede ver, 409 cuando una tarea ya terminó, 429 tras demasiados inicios de sesión fallidos desde la dirección. Cada cambio a través de la API queda en el registro de actividad con el nombre del token.

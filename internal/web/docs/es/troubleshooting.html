Solución de problemas y preguntas frecuentes

Las preguntas más comunes y qué comprobar primero. Para una solicitud de soporte, descargue el diagnóstico en Configuración → Diagnóstico.

No puedo acceder a la consola

  • Puede que su dirección no esté en las redes permitidas: la conexión se cierra antes de TLS, así que el navegador muestra un error de conexión. Ejecute controlzit-server --reset-allowlist en el servidor (appliance: menú de configuración, opción 5) para volver a permitir todas las redes privadas.
  • Tras cambiar el puerto, abra la consola en el puerto nuevo.
  • Compruebe el servicio en el servidor: systemctl status controlzit-server y journalctl -u controlzit-server.

Problemas de inicio de sesión

  • El código es incorrecto: la hora del teléfono debe ser correcta (hora automática).
  • Teléfono perdido: inicie sesión con un código de recuperación; otro administrador puede restablecer el inicio de sesión en dos pasos.
  • Demasiados intentos fallidos: la dirección queda bloqueada un tiempo; un administrador puede desbloquearla en Configuración → Inicio de sesión y seguridad. Los inicios de sesión desde el propio servidor nunca se bloquean.
  • LDAP / inicio de sesión único: use Probar en la página de LDAP; compruebe los grupos que envía el proveedor. El registro del servidor tiene los detalles.

Un agente no se conecta

  • ¿Llega el equipo al puerto de agentes? En Windows: Test-NetConnection rmm.example.com -Port 8444.
  • ¿Es correcta la dirección pública de agentes? Los códigos creados con la consola abierta en localhost envían el agente al servidor equivocado; defina la dirección y cree un código nuevo.
  • ¿Sigue siendo válido el código y no se ha agotado?
  • Registros del agente: Windows C:\ProgramData\ControlZit Agent\agent.log, Linux /var/lib/controlzit-agent/agent.log y journalctl -u controlzit-agent; con el dispositivo conectado, ábralos desde la consola en Archivos. En Windows, el icono junto al reloj muestra el estado de la conexión.

El escritorio remoto no muestra nada

  • Linux con Wayland no se puede mostrar: inicie una sesión X11 (Xorg) o use el terminal.
  • Linux sin escritorio: use el terminal.
  • Copiar archivos por el portapapeles necesita un usuario con sesión iniciada en el equipo Windows.

Las actualizaciones de Windows no se instalan

  • Compruebe la instalación automática en la pestaña Directiva del dispositivo: qué directiva define Windows Update, los días, la hora y el modo. Los dispositivos deben estar en línea en esa hora.
  • La pestaña Actualizaciones del dispositivo muestra la última búsqueda y su error, si lo hay.

No llegan los correos de alerta

Use Enviar un correo de prueba en Configuración → Supervisión y alertas; el mensaje muestra la respuesta del servidor. Una contraseña solo se envía por STARTTLS o TLS.

Preguntas frecuentes

¿Necesita ControlZit un servicio en la nube?

No. Todo se ejecuta en su servidor; no se envía nada a MaxZit. El servidor solo consulta GitHub para ver si hay versiones nuevas.

¿Cómo hago copia de ControlZit?

Haga copia de la base de datos PostgreSQL (pg_dump) y de la carpeta /var/lib/controlzit. Sin la clave secreta y los certificados de ahí, las contraseñas guardadas no se pueden descifrar y los agentes no confiarían en un servidor nuevo.

¿Puedo mover el servidor a otra máquina?

Sí: instale ControlZit en la nueva máquina, restaure la base de datos y /var/lib/controlzit y mantenga la misma dirección (o cambie la dirección pública de agentes y haga que el nombre antiguo apunte a la nueva máquina).

¿Hay un agente para macOS?

Todavía no. Se admiten Windows y Linux (x86-64, ARM64).

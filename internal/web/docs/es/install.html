Instalar el servidor

Elija una de cinco formas. La imagen de VM lista para usar es la más rápida; el script de instalación sirve para un servidor Linux existente y Docker para un host Docker existente.

FormaIdeal paraNecesita
1. Imagen de VM (OVA, qcow2, VHDX)importar, arrancar e iniciar sesión en pocos minutosVMware, Proxmox / KVM o Hyper-V
2. ISO del applianceuna VM nueva o un servidor físico, sin intervenciónacceso a Internet durante la instalación

Todos los archivos están en la página de versiones. Dé al servidor 2 vCPU, 2–4 GB de RAM y un disco de 16 GB o más.

1. Imagen de VM

  1. Importe la imagen:
    • VMware ESXi / Workstation, VirtualBox: despliegue rmmzit-appliance.ova (Create / Register VM → Deploy a virtual machine from an OVF or OVA file).
    • Proxmox VE: cree una VM sin disco (2 vCPU, 2–4 GB de RAM, red VirtIO), copie rmmzit-appliance.qcow2 al nodo y ejecute qm importdisk <vmid> rmmzit-appliance.qcow2 local-lvm; conecte el disco como SCSI y conviértalo en el disco de arranque.
    • Hyper-V: descomprima rmmzit-appliance-vhdx.zip y cree una VM de generación 1 con el VHDX como disco.
  2. Arranque la VM. El disco crece solo hasta el tamaño del disco virtual. La pantalla de la VM muestra la dirección de la consola y el token de configuración.
  3. Abra https://<dirección>:8443. El navegador avisa una vez del certificado autofirmado (sustitúyalo después en Configuración → Certificado). Introduzca el token y cree el primer administrador.

El appliance obtiene su dirección por DHCP. Para una dirección fija, el nombre del servidor o la zona horaria, inicie sesión en la pantalla de la VM como rzadmin (primera contraseña rmmzit, que debe cambiarse): se abre un menú de configuración. La zona horaria y la red también pueden cambiarse después en la consola.

2. ISO del appliance

  1. Arranque una VM o un servidor desde rmmzit-appliance.iso. Tras 5 segundos la instalación empieza sola: borra el primer disco, instala Debian, PostgreSQL y RMMZit y necesita acceso a Internet (10–20 minutos).
  2. Tras reiniciar, la pantalla muestra la dirección de la consola y el token de configuración, como con la imagen de VM.

3. Script de instalación

En un servidor Linux existente, como root:

curl -fsSL https://github.com/Max-Zit/rmmzit/releases/latest/download/install.sh | sudo sh

El script instala PostgreSQL, descarga la versión más reciente, comprueba su firma, crea una base de datos con una contraseña aleatoria e inicia el servicio. Opciones (después de sh -s --): --version X, --db postgres://… para una base existente, --no-auto-updates para dejar desactivadas las actualizaciones de seguridad automáticas del sistema operativo. Ejecutarlo de nuevo actualiza RMMZit y conserva los datos.

4. Paquetes a mano

sudo apt install ./rmmzit-server_X_amd64.deb      # Debian, Ubuntu
sudo dnf install ./rmmzit-server-X-1.x86_64.rpm     # AlmaLinux, Rocky Linux

Después escriba la dirección de la base de datos en /etc/rmmzit/server.env (RMMZIT_DB=postgres://…) e inicie el servicio con systemctl enable --now rmmzit-server.

5. Docker

El servidor también es una imagen de contenedor, ghcr.io/max-zit/rmmzit, creada a partir del mismo paquete de servidor firmado que las demás formas; funciona con PostgreSQL mediante Docker Compose. Descargue docker-compose.yml y .env.example en una carpeta, copie .env.example a .env, defina una contraseña de base de datos (letras y dígitos) y la zona horaria y luego:

docker compose up -d
docker compose exec rmmzit cat /var/lib/rmmzit/setup-token.txt

Abra https://<host>:8443 e introduzca el token de configuración. El puerto 8444 es el punto de conexión de los agentes; ábralo donde se conecten los agentes. La etiqueta de la imagen en .env decide qué se ejecuta: latest para las versiones oficiales, testing para las versiones candidatas.

Actualice con docker compose pull && docker compose up -d. Antes de que una nueva versión cambie la base de datos, el servidor escribe una copia en Configuración → Copia de la consola. Para volver atrás, ponga la versión anterior como etiqueta de la imagen y restaure ese archivo: docker compose stop rmmzit, docker compose run --rm rmmzit -restore /var/lib/rmmzit/backups/ARCHIVO, docker compose up -d. En un contenedor, la red y la zona horaria dependen del host Docker, no de la consola.

Primer inicio de sesión

  • El token de configuración está en /var/lib/rmmzit/setup-token.txt y en el registro del servidor (journalctl -u rmmzit-server). Sirve una sola vez.
  • Cada cuenta necesita una aplicación de autenticación (TOTP) y recibe 10 códigos de recuperación. Guárdelos en un lugar seguro.
  • De forma predeterminada la consola solo acepta conexiones de redes privadas. Si se queda sin acceso, ejecute rmmzit-server --reset-allowlist en el servidor (appliance: menú de configuración, opción 5).

Dónde está cada cosa

RutaQué
/etc/rmmzit/server.envconfiguración: base de datos, puertos, origen de actualizaciones (solo la leen root y el servicio)
/var/lib/rmmzitdirectorio de datos: certificados, clave secreta, instaladores de agentes (downloads), registros
/var/lib/rmmzit/logs/server.logregistro del servidor; también en journalctl -u rmmzit-server
/var/log/rmmzit-helperregistro del asistente root (actualizaciones, zona horaria, red)

Haga copia de la base de datos junto con /var/lib/rmmzit: la clave secreta de ahí descifra las contraseñas guardadas y los certificados identifican al servidor ante sus agentes.

Primeros pasos

ControlZit es una herramienta de supervisión y gestión remota (RMM) autoalojada. Desde una consola web en su propio servidor supervisa y gestiona los equipos Windows y Linux de sus clientes: inventario, supervisión y alertas, escritorio remoto, terminal, archivos, scripts, actualizaciones de Windows, software e informes.

Qué hace ControlZit

ÁreaQué obtiene
InventarioHardware, sistema operativo, discos, red, estado de seguridad (antivirus, cortafuegos, BitLocker) y software instalado de cada dispositivo. Dispositivos
Supervisión y alertasCPU, memoria, espacio en disco, dispositivos sin conexión, servicios detenidos, Defender y cortafuegos; alertas por correo, Slack, Microsoft Teams o webhook. Supervisión
Acceso remotoEscritorio remoto en el navegador (Windows, Linux con X11) con portapapeles y copia de archivos, terminal root en Linux, gestor de archivos, procesos, servicios, reinicio y apagado. Acceso remoto
ScriptsPowerShell, cmd, bash o sh en un dispositivo, en muchos a la vez o según una programación, desde una biblioteca de scripts. Scripts
Actualizaciones y softwareActualizaciones de Windows y paquetes de Linux que faltan, instalación a mano o programada, programas mediante winget. Actualizaciones
InformesUn informe por cliente (dispositivos, actualizaciones, alertas, trabajo de los técnicos), imprimible o enviado por correo cada semana o mes. Informes

Cómo funciona

  • El servidor se ejecuta en una máquina Linux (normalmente una VM pequeña) con PostgreSQL. Tiene dos puertos: la consola (interfaz web y API, TCP 8443) y el punto de conexión de agentes (TCP 8444).
  • Los agentes se ejecutan como servicio en cada equipo gestionado. Se conectan de forma saliente al puerto de agentes; los equipos no necesitan puertos abiertos. Un agente confía en el servidor por la huella de su certificado, que fija al registrarse.
  • Cada comando a un agente lo firma el servidor y lo comprueba el agente, y cada acción se anota en el registro de auditoría a prueba de manipulaciones.

La consola controla cada equipo gestionado. Haga que solo sea accesible desde sus propias redes (lo predeterminado) y abra solo el puerto de agentes donde los agentes lo necesiten. Consulte Seguridad.

Primeros pasos

  1. Instale el servidor: importe la imagen de VM lista para usar, arranque la ISO del appliance o ejecute el script de instalación en un servidor Linux. Consulte Instalar el servidor.
  2. Cree el primer administrador con el token de configuración que muestra el servidor y configure el inicio de sesión en dos pasos con una aplicación de autenticación.
  3. Compruebe la dirección de agentes en Configuración → Red y acceso: los agentes deben llegar al servidor por la dirección pública de agentes o el nombre de host de la consola.
  4. Añada un cliente y una sede en Clientes y cree un código de registro en la sede.
  5. Instale el agente en los equipos de esa sede con el código. Consulte Instalar agentes.
  6. Configure las alertas en Configuración → Supervisión y alertas y, si lo desea, la instalación automática de actualizaciones de Windows.
  7. Añada a sus técnicos en Usuarios, o conecte Active Directory / LDAP o el inicio de sesión único. Consulte Usuarios, roles e inicio de sesión.

Requisitos

  • Servidor: 2 vCPU, 2–4 GB de RAM, disco de 16 GB; Debian 12+, Ubuntu 22.04+, AlmaLinux o Rocky Linux 9+ (o el appliance listo para usar).
  • Agentes de Windows: Windows 10 / 11, Windows Server 2016 y posterior, 64 bits.
  • Agentes de Linux: distribuciones con systemd, x86-64 o ARM64 (Raspberry Pi y servidores ARM). Actualizaciones mediante apt o dnf.
  • Navegador: Chrome, Edge, Firefox o Safari actuales.

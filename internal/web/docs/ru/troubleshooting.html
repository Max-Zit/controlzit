Устранение неполадок и FAQ

Самые частые вопросы и что проверить в первую очередь. Для обращения в поддержку скачайте диагностику в разделе Настройки → Диагностика.

Не открывается консоль

  • Возможно, вашего адреса нет в разрешённых сетях: соединение закрывается до TLS, поэтому браузер показывает ошибку соединения. Выполните на сервере controlzit-server --reset-allowlist (устройство: меню настройки, пункт 5), чтобы снова разрешить все частные сети.
  • После смены порта откройте консоль на новом порту.
  • Проверьте службу на сервере: systemctl status controlzit-server и journalctl -u controlzit-server.

Проблемы со входом

  • Код неверен — время на телефоне должно быть точным (автоматическое время).
  • Потерян телефон — войдите с резервным кодом; другой администратор может сбросить двухфакторный вход.
  • Слишком много неудачных попыток — адрес на время заблокирован; администратор может разблокировать его в разделе Настройки → Вход и безопасность. Входы с самого сервера никогда не блокируются.
  • LDAP / единый вход — используйте Проверить на странице LDAP; проверьте группы, которые отправляет поставщик. Подробности есть в журнале сервера.

Агент не подключается

  • Достигает ли компьютер порта агентов? В Windows: Test-NetConnection rmm.example.com -Port 8444.
  • Правилен ли публичный адрес для агентов? Коды, созданные при консоли, открытой через localhost, направляют агента не на тот сервер; задайте адрес и создайте новый код.
  • Действует ли ещё код и не исчерпан ли он?
  • Журналы агента: Windows C:\ProgramData\ControlZit Agent\agent.log, Linux /var/lib/controlzit-agent/agent.log и journalctl -u controlzit-agent; для подключённого устройства откройте их из консоли в разделе Файлы. В Windows значок рядом с часами показывает состояние соединения.

Удалённый рабочий стол ничего не показывает

  • Linux с Wayland показать нельзя: войдите в сеанс X11 (Xorg) или используйте терминал.
  • Linux без рабочего стола: используйте терминал.
  • Для копирования файлов через буфер обмена на компьютере с Windows должен быть вошедший пользователь.

Обновления Windows не устанавливаются

  • Проверьте автоматическую установку на вкладке Политика устройства: какая политика задаёт Windows Update, дни, час и режим. В этот час устройства должны быть в сети.
  • Вкладка Обновления устройства показывает последний поиск и его ошибку, если она есть.

Письма об оповещениях не приходят

Используйте Отправить тестовое письмо в разделе Настройки → Мониторинг и оповещения; сообщение покажет ответ сервера. Пароль отправляется только через STARTTLS или TLS.

FAQ

Нужен ли ControlZit облачный сервис?

Нет. Всё работает на вашем сервере; ничего не отправляется в MaxZit. Сервер только проверяет GitHub на наличие новых выпусков.

Как сделать резервную копию ControlZit?

В разделе Настройки → Резервная копия консоли сервер каждый день сохраняет базу данных, секретный ключ и сертификаты, по желанию в зашифрованном виде и с копией на SFTP-сервер. Храните копию вне сервера: без секретного ключа сохранённые пароли не расшифровать, а агенты не будут доверять новому серверу.

Можно ли перенести сервер на новую машину?

Да: установите ControlZit на новую машину и восстановите там резервную копию консоли (controlzit-server -restore ФАЙЛ, на appliance пункт 7 меню настройки). Сохраните тот же адрес или измените публичный адрес для агентов и направьте старое имя на новую машину; агенты продолжают работать, потому что копия содержит сертификаты сервера.

Есть ли агент для macOS?

Пока нет. Поддерживаются Windows и Linux (x86-64, ARM64).

Безопасность

RMM-сервер может управлять каждым компьютером, который он обслуживает. ControlZit построен так, чтобы злоумышленник, добравшийся до консоли, сети или даже сервера, получил как можно меньше.

Как ControlZit вас защищает

  • Два порта. Консоль и точка подключения агентов слушают на разных портах. Консоль принимает соединения только из разрешённых сетей, с проверкой до TLS; порт агентов может быть публичным, не раскрывая консоль.
  • Исходящие агенты. Агенты подключаются к серверу; управляемым компьютерам не нужны открытые порты. Агенты закрепляют сертификат сервера по отпечатку, поэтому поддельный сервер не сможет их захватить.
  • Подписанные команды. Каждая команда агенту подписывается ключом команд сервера и проверяется агентом; обновления агентов должны совпадать с SHA-256 в подписанной команде.
  • Надёжный вход. Двухфакторный вход для каждой локальной и каталожной учётной записи, пароли argon2id, короткие сеансы, выход после бездействия, нарастающая блокировка неудачных входов.
  • Защита браузера. Проверки CSRF при каждом изменении, строгая Content Security Policy без встроенных скриптов, cookie сеанса __Host-.
  • Минимальные права. Роли и доступ по клиентам; консоль работает от непривилегированного пользователя, а немногие действия root (обновления, сеть, часовой пояс) идут через отдельного помощника root, который принимает только фиксированные проверенные запросы.
  • Аудит. Журнал аудита, связанный цепочкой хешей, для каждого изменения и каждого удалённого действия.
  • Подписанные выпуски. Сервер, агенты и install.sh устанавливают только выпуски, подписанные ключом выпусков ControlZit.
  • Секреты. Сохранённые пароли (почта, LDAP, каналы, Cloudflare) шифруются секретным ключом сервера; диагностика удаляет секреты.

Рекомендации

  1. Делайте консоль доступной только из административных сетей; для доступа извне используйте VPN (например, WireGuard), а не открывайте порт консоли.
  2. Открывайте порт агентов только там, где есть агенты, и задайте сети агентов, если все они подключаются с известных адресов.
  3. Используйте сертификат, которому доверяют браузеры (Let's Encrypt или ваш ЦС), чтобы пользователи не привыкали пропускать предупреждения.
  4. Дайте каждому человеку свою учётную запись с минимальной ролью и только нужными клиентами; отключайте учётные записи уволившихся.
  5. Оставьте одного локального администратора на экстренный случай, с резервными кодами, хранящимися офлайн.
  6. Быстро устанавливайте обновления ControlZit (или включите автоматические) и поддерживайте ОС сервера в актуальном состоянии; устройство само устанавливает обновления безопасности Debian.
  7. Регулярно делайте резервные копии базы данных и /var/lib/controlzit и храните их вдали от сервера.
  8. Время от времени просматривайте журнал аудита и оставляйте включённым уведомление на удалённом экране, чтобы пользователи знали, когда кто-то подключён.

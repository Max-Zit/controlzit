API

REST API позволяет скриптам и другим инструментам читать устройства, оповещения и задачи и запускать работу на устройствах с теми же правами, что и в консоли.

Токены

Создайте токен в разделе Моя учётная запись → API-токены: название, роль не выше вашей (только чтение, техник или администратор) и срок действия. Токен показывается один раз; храните его как пароль. Он действует от вашего имени, с вашими клиентами. Передавайте его в каждом запросе как Authorization: Bearer czt_… на адрес консоли (порт 8443), который принимает подключения только из разрешённых сетей. Сеансовые cookie браузера в API не работают. Удаление токена на странице учётной записи сразу прекращает его доступ.

Задачи

Задача ждёт, пока устройство будет в сети, и выполняется после предыдущих задач устройства, как действия в консоли; она видна в разделе «Действия» устройства. Ответ — 202 с задачей; следите за ней через GET /api/v1/tasks/{id}, пока её статус не станет done, failed, cancelled или expired. Виды задач и их поля:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Примеры

Скрипт PowerShell на устройстве 9, затем его результат:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Ошибки

Ошибки приходят как JSON {"error": "…"} с HTTP-статусом: 400 — неверный запрос, 401 — токен отсутствует, неверен или истёк, 403 — роль токена не разрешает вызов, 404 — объект не существует или токену его не видно, 409 — задача уже завершена, 429 — слишком много неудачных входов с этого адреса. Каждое изменение через API записывается в журнал действий с названием токена.

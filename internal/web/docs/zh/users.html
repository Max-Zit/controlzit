用户、角色与登录

每个人都使用自己的账户登录。角色决定可以做什么，客户访问权限决定可以看到什么，每个操作都会以其名义写入审计日志。

角色

角色可以
管理员所有操作，包括用户和设置；始终可以看到所有客户
技术员管理允许客户的设备：远程访问、脚本、更新、程序、警报
只读只能查看允许的客户：设备、警报、更新、报告

技术员和只读用户可以访问所有客户（包括将来的客户）或仅部分客户。

本地账户

在用户中，管理员使用初始密码添加用户；用户必须在首次登录时更改密码并设置双重验证登录。管理员可以禁用用户（已打开的会话将结束）、设置新密码，或为丢失手机和恢复码的用户重置双重验证登录。系统始终至少保留一个已启用的管理员。

双重验证登录

ControlZit 对每台受管计算机都有管理员权限，因此每个本地账户和目录账户都需要身份验证器应用（Microsoft Authenticator、Google Authenticator、Authy、1Password、Bitwarden …）。每个账户还会获得 10 个一次性恢复码；可在账户中生成新的恢复码。登录失败会在一段时间内封锁该地址（每次重复封锁后时间更长）；相关限制以及会话时长和闲置退出位于设置 → 登录与安全。

Active Directory / LDAP

在设置 → Active Directory / LDAP中，用户使用目录账户登录。目录检查密码；ControlZit 仍会要求自己的第二重验证。

  • 服务器：ldaps://dc1.example.local（端口 636），或使用 StartTLS 的 ldap://（389）——密码永远不会以未加密方式通过网络。如果目录的证书来自公司 CA，请添加 CA 证书。
  • 服务账户（DN 或 user@domain）及其密码、基准 DN 和用户筛选器，例如 Active Directory 的 (&(objectClass=user)(sAMAccountName={username}))。
  • 组与角色：将目录组映射到管理员、技术员和只读角色；最高角色优先。可以包含 Active Directory 的嵌套组。
  • 客户组：组 = 客户 形式的行将技术员和只读用户限制为这些客户。

测试使用已保存的设置检查目录账户（不登录），并显示 ControlZit 会如何处理该账户。目录账户在目录中更改密码，而不是在 ControlZit 中。

单点登录（OpenID Connect、SAML）

在设置 → 单点登录中，用户使用其在身份提供商处的账户登录：OpenID Connect（Microsoft Entra ID、Google、Okta、Keycloak …）或 SAML 2.0（ADFS、Entra ID、Okta …）。登录页面随后会显示一个按钮。

  • OpenID Connect：在提供商处使用页面上显示的重定向 URI 注册应用，然后输入颁发者（例如 https://login.microsoftonline.com/<tenant>/v2.0）、客户端 ID 和客户端密钥。
  • SAML：向提供商提供控制台的元数据（页面上的链接）或其 entity ID 和回复（ACS）地址，然后输入提供商的元数据 URL 或粘贴其 XML。
  • 组声明携带组（名称或 ID；Entra ID 发送组 ID），并像 LDAP 一样映射到角色和客户。
  • 身份提供商的多重身份验证策略适用；ControlZit 也可以选择额外要求自己的第二重验证。

启用 LDAP 或单点登录后，本地账户仍然有效，因此管理员始终可以登录。请保留一个本地管理员以备紧急情况。

审计日志

审计日志列出每次更改和每个远程操作，以及用户、对象（客户、站点、设备或用户，带链接）和地址。记录通过哈希链相连；控制台每次查看时都会检查链，并在有记录被修改或删除时报告。

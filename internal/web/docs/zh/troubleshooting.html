故障排除与常见问题

最常见的问题以及首先要检查的内容。如需提交支持请求，请在设置 → 诊断中下载诊断信息。

无法访问控制台

  • 您的地址可能不在允许的网络中：连接在 TLS 之前即被关闭，因此浏览器显示连接错误。在服务器上运行 controlzit-server --reset-allowlist（设备：设置菜单第 5 项）可重新允许所有私有网络。
  • 更改端口后，请在新端口上打开控制台。
  • 检查服务器上的服务：systemctl status controlzit-server 和 journalctl -u controlzit-server。

登录问题

  • 验证码错误——手机时间必须正确（自动时间）。
  • 手机丢失——使用恢复码登录；其他管理员可以重置双重验证登录。
  • 失败次数过多——该地址会被封锁一段时间；管理员可以在设置 → 登录与安全中解除封锁。来自服务器本身的登录永远不会被封锁。
  • LDAP / 单点登录——在 LDAP 页面使用测试；检查提供商发送的组。服务器日志中有详细信息。

代理无法连接

  • 计算机能否访问代理端口？在 Windows 上：Test-NetConnection rmm.example.com -Port 8444。
  • 代理公网地址是否正确？在通过 localhost 打开控制台时创建的注册码会把代理指向错误的服务器；请设置地址并创建新的注册码。
  • 注册码是否仍然有效且未用完？
  • 代理日志：Windows C:\ProgramData\ControlZit Agent\agent.log，Linux /var/lib/controlzit-agent/agent.log 和 journalctl -u controlzit-agent；对于已连接的设备，可在控制台的文件中打开。在 Windows 上，时钟旁的图标显示连接状态。

远程桌面什么都不显示

  • 无法显示使用 Wayland 的 Linux：请使用 X11（Xorg）会话登录或使用终端。
  • 没有桌面的 Linux：请使用终端。
  • 通过剪贴板复制文件需要 Windows 计算机上有已登录的用户。

Windows 更新未安装

  • 在设置 → Windows 更新中检查自动安装：日期、小时和模式。设备必须在该小时内在线。
  • 设备的更新选项卡显示上次搜索及其错误（如果有）。

收不到警报邮件

在设置 → 监控与警报中使用发送测试邮件；消息会显示服务器的响应。密码只通过 STARTTLS 或 TLS 发送。

常见问题

ControlZit 需要云服务吗？

不需要。一切都在您的服务器上运行；不会向 MaxZit 发送任何内容。服务器只会检查 GitHub 上是否有新版本。

如何备份 ControlZit？

备份 PostgreSQL 数据库（pg_dump）和 /var/lib/controlzit 文件夹。如果没有其中的密钥和证书，已保存的密码将无法解密，代理也不会信任新服务器。

可以把服务器迁移到新机器吗？

可以：在新机器上安装 ControlZit，恢复数据库和 /var/lib/controlzit，并保持相同的地址（或更改代理公网地址，并将旧名称指向新机器）。

有 macOS 代理吗？

暂时没有。支持 Windows 和 Linux（x86-64、ARM64）。

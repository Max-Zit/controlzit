Windows 更新与软件

RMMZit 显示每台计算机缺少哪些更新，并可手动或按您的计划安装。程序通过 winget 安装和更新。

概览

更新列出缺少更新的设备（安全更新单独统计）、等待重启的设备、上次安装和上次搜索。代理在启动几分钟后搜索缺少的更新，之后每天搜索两次；立即搜索会立刻开始搜索。

在一台设备上

设备的更新选项卡列出缺少的更新及其类别和严重性，以及最近安装的更新。选择更新并点击安装所选；安装作为任务在活动中运行，完成后会显示结果。如果需要重启，设备会显示提示，您可以从其页面重启。

Defender 定义（Security Intelligence Update）每天发布多次，每次都有新的更新 ID。安装时，代理会先重新搜索，然后安装 Windows Update 当时提供的定义版本。

自动安装

策略的 Windows Update 部分（例如客户的策略 Default）选择服务器自动安装的内容：

  • 关闭——仅从控制台安装更新。
  • 安全和关键更新、Defender 定义。
  • 除功能升级外的所有更新——Windows 新版本永远不会自动安装。

选择日期和小时（服务器时间），或选择在维护时间窗口内。届时在线的设备在当天安装一次；离线设备等待下一个计划日期。

更新环：例如设置 7 天延迟后，设备只会在服务器首次发现某个更新 7 天后才安装它。为测试计算机分配 0 天的策略，为其他计算机分配 7 天的策略，问题就会先在测试计算机上出现。Defender 定义从不等待。

更新需要时重启：从不自动；安装后 5 分钟自动重启并发出通知；或询问用户：RMMZit 图标请求已登录用户重启，每 4 小时提醒一次，期限（用户可推迟的天数）过后，服务器提前 10 分钟通知并重启计算机；如果设备有维护时间窗口，则在窗口内重启。设备的策略选项卡会显示待处理的重启及其期限。

为避免更新在随机时间到来，代理会通过策略关闭 Windows 更新的自动安装。移除代理后，之前的设置会恢复。

Linux

在 Linux 上，代理通过 apt（Debian、Ubuntu；安全更新来自 -security 源）或 dnf（RHEL 系列；安全更新依据更新信息）读取可用的软件包更新，并安装所选软件包。自动安装同样适用于 Linux 设备；在那里，“安全更新”指来自安全源的软件包。

程序（winget）

Windows 设备的程序选项卡分为三部分。可用更新列出 winget 可以更新的程序；全部更新会更新它们，也可以单独更新程序。已安装列出 Windows 已安装程序列表中的每个程序，包括计算机级和已登录用户的程序，并可按名称或发布者筛选。卸载以静默方式删除程序：Windows Installer（MSI）包使用 msiexec /x，Inno Setup 和 NSIS 卸载程序使用其静默参数，或使用程序自带的静默命令。只有在程序确实被删除后才会报告结果；没有静默卸载程序的程序会被标记，需要在计算机上或通过脚本删除。安装程序在 winget 社区存储库中搜索（例如 7-Zip 或 Chrome），并为所有用户静默安装。安装和更新需要 winget（App Installer），当前的 Windows 10 和 11 已自带。

可以在软件 → 公共来源中添加 Chocolatey 作为第二个公共来源。之后，安装程序会提供来源选择（winget 或 Chocolatey），可用更新也会列出通过 Chocolatey 安装且有更新版本的程序。Chocolatey 客户端会在设备上首次需要时通过 winget 安装。Chocolatey 软件包由其社区维护，通常从厂商网站下载程序。

软件库

管理员在软件中上传自己的安装程序：Windows Installer 包（.msi）或安装程序（.exe），最大 2 GB，并填写名称、版本、静默安装参数以及表示成功的退出代码（默认 0、1641 和 3010；后两个表示重启后即可完成安装）。对于 MSI，代理会运行带日志的 msiexec /i，默认参数为 /qn /norestart；EXE 需要其自身的静默参数，例如 /S（NSIS）、/VERYSILENT /NORESTART（Inno Setup）或 /quiet。

安装到设备可选择客户、站点或单个 Windows 设备，并像库脚本一样启动任务：在线设备立即安装，离线设备在 24 小时内连接时安装。代理从服务器的代理端口下载安装程序，并在以 SYSTEM 身份运行之前根据签名命令中的 SHA-256 进行校验。任务页面显示每台设备的结果；Windows Installer 包的日志随结果一起保存。技术人员可以在其客户的设备上安装软件包，也可以在设备“程序”选项卡的安装程序中安装。

漏洞

管理员在漏洞页面开启对已安装程序的扫描。服务器每 6 小时将其与公开漏洞数据库进行比较：常见 Windows 程序（浏览器、PDF 阅读器、压缩工具、远程访问和开发工具等）使用 NVD，Debian 和 Ubuntu 的软件包使用 OSV。只发送程序名称和版本，从不发送设备数据。可选的免费 NVD API 密钥可加快首次扫描。

该页面列出受影响的程序和版本，以及按严重程度统计的漏洞数量和设备；设备的漏洞选项卡列出每个漏洞并附有说明链接。更新程序即可修复。在策略的警报规则中选择程序存在严重漏洞时发出警报后，严重漏洞（CVSS 9 及以上）会产生警报。Windows 本身由 Windows 更新负责，不在此扫描范围内。

设备发行版中尚无修复的 Debian 和 Ubuntu 软件包漏洞默认隐藏，可选择显示；每个结果都会显示修复它的版本。

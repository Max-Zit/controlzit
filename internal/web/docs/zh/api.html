API

REST API 让脚本和其他工具可以读取设备、警报和任务，并在设备上启动工作，权限与控制台相同。

令牌

在我的帐户 → API 令牌中创建令牌：名称、不高于您的角色（只读、技术人员或管理员）以及有效期。令牌只显示一次；请像密码一样保存。它以您的身份（使用您的客户）操作。每次请求都以 Authorization: Bearer czt_… 的形式发送到控制台地址（端口 8443），该地址只接受来自允许网络的连接。浏览器的会话 Cookie 对 API 无效。在帐户页面删除令牌会立即终止其访问。

调用

调用作用
GET /api/v1/me令牌以谁的身份操作、其角色和客户
GET /api/v1/customers客户
GET /api/v1/customers/{id}/sites客户的站点
GET /api/v1/devices?customer=&site=&q=设备，可按客户、站点或搜索文字筛选
GET /api/v1/devices/{id}单台设备及其清单
GET /api/v1/devices/{id}/tasks设备的任务（运行中、等待中以及最近完成的 100 个）
POST /api/v1/devices/{id}/tasks在设备上启动任务（技术人员）
GET /api/v1/tasks/{id}单个任务，用于跟踪直到结束
POST /api/v1/tasks/{id}/cancel停止运行中的任务或取消等待中的任务（技术人员）
GET /api/v1/alerts?state=open未解决的警报（state=all 也包括已解决的）
GET /api/v1/software软件库中的软件包（技术人员）
POST /api/v1/software/{id}/install以任务方式将库中的软件包安装到设备（技术人员）
GET /api/v1/jobs/{id}任务在每台设备上的结果（技术人员）
GET /api/v1/policies策略及其分配（管理员）
POST /api/v1/policies/{id}/assign将策略分配给 customer:ID、site:ID 或 device:ID（管理员）
POST /api/v1/policies/unassign移除客户、站点或设备的策略（管理员）

任务

任务会等待设备上线，并在设备之前的任务之后运行，与控制台中的操作相同；它显示在设备的活动中。响应为带有任务的 202；使用 GET /api/v1/tasks/{id} 跟踪，直到其状态为 done、failed、cancelled 或 expired。任务类型及其字段：

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

示例

在设备 9 上运行 PowerShell 脚本，然后查看结果：

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

错误

错误以 JSON {"error": "…"} 和 HTTP 状态返回：400 表示请求错误，401 表示令牌缺失、错误或已过期，403 表示令牌的角色不允许此调用，404 表示对象不存在或令牌无权查看，409 表示任务已结束，429 表示该地址登录失败次数过多。通过 API 进行的每项更改都会连同令牌名称记录到审核日志中。

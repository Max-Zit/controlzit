监控、警报与通知

服务器每分钟检查每台设备一次。只要条件持续，警报就保持打开，条件消失后自动关闭；您会通过电子邮件、聊天频道或 Webhook 收到通知。

警报规则

在客户、站点和设备的策略中设置规则（每个客户都有自己的策略 Default）。警报邮件、邮件服务器和聊天渠道位于设置 → 监控与警报。

警报分为警告和严重（严重：离线设备、已停止的服务、Defender 已关闭，以及可用空间少于 1 GB 或使用率达 98 % 的磁盘）。警报列出未处理的警报（也可显示已解决的）；技术员可以确认警报，让其他人看到已有人在处理。未处理警报的数量会显示在菜单中。

网络检查

策略的网络检查部分列出策略中每台设备每分钟从自己的网络检查的地址：ping（路由器、打印机、服务器）、TCP 端口（例如 1433 上的数据库）或网址，网址必须无 HTTP 错误地响应并带有效证书。检查失败超过设定的分钟数时会产生警报，网址证书到期前 14 天也会产生警报。设备概览会显示每项检查及其响应时间。

磁盘健康

设备每小时报告一次物理磁盘的健康状况：在 Windows 上为磁盘向 Windows 报告的信息（SMART：状态、温度、SSD 磨损、未纠正错误）以及存储空间磁盘；在 Linux 上为通过 smartctl（smartmontools 软件包）获取的 SMART 和 md 软件 RAID 阵列。报告问题的磁盘和降级的 RAID 阵列会产生警报，除非策略的警报规则关闭此项。硬件 RAID 控制器后面的磁盘对系统不可见，不在范围内。设备概览会显示磁盘。

警报邮件

  1. 输入邮件服务器（SMTP）：主机、端口、连接安全（STARTTLS 或 TLS；密码永远不会通过未加密的连接发送）、用户、密码和发件人。密码以加密方式存储。
  2. 添加收件人，每行一个地址，并选择警报解决时是否也发送邮件。
  3. 点击发送测试邮件。

Slack、Microsoft Teams 和 Webhook

在聊天和 Webhook下最多添加 20 个频道：

  • Slack——频道的传入 Webhook URL。
  • Microsoft Teams——频道工作流“收到 Teams Webhook 请求时”及其 URL。
  • Webhook——任何接受 JSON POST 的 HTTPS URL（工单系统、自动化）。设置密钥后，每个请求都带有 X-ControlZit-Signature: sha256=<请求体的 HMAC>，接收方可以据此验证请求来自您的服务器。

为每个频道选择所有警报或仅严重警报，以及是否也发送已解决的警报。发送测试会发送一条测试消息。频道地址以加密方式存储。

实时数值

设备页面显示当前的 CPU 负载、内存和磁盘，以及未运行的自动服务。

历史记录与磁盘预测

设备的 History 选项卡会绘制 24 小时、7 天、30 天或 90 天内的 CPU 负载、内存、网络流量（0.11 及以上版本的代理）以及每个磁盘的已用空间。每分钟的数值保留 7 天，每小时的汇总保留 90 天。

服务器根据每小时的磁盘空间计算：如果磁盘继续按过去 14 天的速度增长，何时会写满。90 天内将写满的磁盘会显示在设备页面上；告警规则 磁盘即将写满 会在策略设定的天数内打开告警（新策略为 14 天；3 天内为严重）。

监视器：事件和进程

策略的 Monitors 部分监视 Windows 事件日志以及必须运行的程序。每 5 分钟询问一次策略中的设备（需要 0.12 及以上版本的代理）。

  • 事件规则：一个日志（System、Application、Security 或 Setup），可选事件 ID、来源和级别，以及在多少分钟内出现多少个匹配事件时打开告警（警告或严重）。示例：Security 4625（登录失败）10 分钟内 5 次；System 41（意外重启）；System 7031 和 7034（服务意外终止）。Security 日志的事件没有级别：请将级别保持为任意。
  • 必须运行的进程：程序名，例如 sqlservr.exe（Windows）或 nginx（Linux）；程序未运行期间告警保持打开。

设备页面显示每条规则及其最近一次结果。条件消失后告警会自动关闭。

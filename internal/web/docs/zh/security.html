安全

RMM 服务器可以控制它管理的每台计算机。RMMZit 的设计目标是：即使攻击者到达控制台、网络甚至服务器，也只能得到尽可能少的东西。

RMMZit 如何保护您

  • 两个端口。控制台和代理端点监听不同的端口。控制台只接受来自允许网络的连接，并在 TLS 之前检查；代理端口可以公开而不暴露控制台。
  • 出站代理。代理连接到服务器；受管计算机无需开放端口。代理通过指纹固定服务器证书，因此伪造的服务器无法接管它们。
  • 已签名的命令。发给代理的每条命令都使用服务器的命令密钥签名并由代理验证；代理更新必须与已签名命令中的 SHA-256 一致。
  • 强登录。每个本地和目录账户都使用双重验证登录、argon2id 密码、短会话、闲置后退出，以及对登录失败逐步加长的封锁。
  • 浏览器防护。每次更改都进行 CSRF 检查，严格的 Content Security Policy（无内联脚本），__Host- 会话 Cookie。
  • 最小权限。按角色和客户授予访问；控制台以非特权用户运行，少量 root 操作（更新、网络、时区）通过单独的 root 助手执行，它只接受固定且经过验证的请求。
  • 审计。每次更改和每个远程操作都记录在哈希链审计日志中。
  • 已签名的版本。服务器、代理和 install.sh 只安装使用 RMMZit 发布密钥签名的版本。
  • 机密。已保存的密码（邮件、LDAP、频道、Cloudflare）使用服务器的密钥加密；诊断会去除机密。

最佳实践

  1. 仅允许从您的管理网络访问控制台；如需从外部访问，请使用 VPN（例如 WireGuard），而不是开放控制台端口。
  2. 只在有代理的地方开放代理端口；如果所有代理都来自已知地址，请设置代理网络。
  3. 使用浏览器信任的证书（Let's Encrypt 或您的 CA），以免用户习惯于忽略警告。
  4. 为每个人分配自己的账户，授予最小角色和所需的客户；禁用离职人员的账户。
  5. 保留一个本地管理员以备紧急情况，并将其恢复码离线保存。
  6. 尽快安装 RMMZit 更新（或启用自动更新），并保持服务器操作系统为最新；设备会自动安装 Debian 安全更新。
  7. 定期备份数据库和 /var/lib/rmmzit，并将备份存放在远离服务器的地方。
  8. 不时检查审计日志，并保持远程屏幕提示开启，让用户知道何时有人连接。

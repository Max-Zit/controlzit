API

REST API pozwala skryptom i innym narzędziom odczytywać urządzenia, alerty i zadania oraz uruchamiać pracę na urządzeniach, z tymi samymi uprawnieniami co w konsoli.

Tokeny

Token tworzy się w Moje konto → Tokeny API: nazwa, rola nie wyższa niż Twoja (tylko odczyt, technik lub administrator) i okres ważności. Token jest pokazywany tylko raz; przechowuj go jak hasło. Działa w Twoim imieniu, z Twoimi klientami. Wysyłaj go w każdym żądaniu jako Authorization: Bearer czt_… na adres konsoli (port 8443), który przyjmuje połączenia tylko z dozwolonych sieci. Pliki cookie sesji przeglądarki nie działają w API. Usunięcie tokenu na stronie konta natychmiast kończy jego dostęp.

Zadania

Zadanie czeka, aż urządzenie będzie online, i wykonuje się po wcześniejszych zadaniach urządzenia, tak jak akcje w konsoli; widać je w Aktywności urządzenia. Odpowiedzią jest 202 z zadaniem; śledź je przez GET /api/v1/tasks/{id}, aż jego stan będzie done, failed, cancelled lub expired. Rodzaje i ich pola:

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Przykłady

Skrypt PowerShell na urządzeniu 9, a potem jego wynik:

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Błędy

Błędy przychodzą jako JSON {"error": "…"} ze statusem HTTP: 400 dla nieprawidłowego żądania, 401 dla brakującego, błędnego lub wygasłego tokenu, 403, gdy rola tokenu nie pozwala na wywołanie, 404 dla czegoś, co nie istnieje lub czego token nie może widzieć, 409, gdy zadanie już się zakończyło, 429 po zbyt wielu nieudanych logowaniach z adresu. Każda zmiana przez API trafia do dziennika aktywności z nazwą tokenu.

Installer le serveur

Choisissez l'une des cinq méthodes. L'image VM prête à l'emploi est la plus rapide ; le script d'installation convient à un serveur Linux existant, Docker à un hôte Docker existant.

Tous les fichiers sont sur la page des versions. Donnez au serveur 2 vCPU, 2–4 Go de RAM et un disque d'au moins 16 Go.

1. Image VM

  1. Importez l'image :
    • VMware ESXi / Workstation, VirtualBox : déployez rmmzit-appliance.ova (Create / Register VM → Deploy a virtual machine from an OVF or OVA file).
    • Proxmox VE : créez une VM sans disque (2 vCPU, 2–4 Go de RAM, réseau VirtIO), copiez rmmzit-appliance.qcow2 sur le nœud et lancez qm importdisk <vmid> rmmzit-appliance.qcow2 local-lvm ; attachez le disque en SCSI et faites-en le disque de démarrage.
    • Hyper-V : décompressez rmmzit-appliance-vhdx.zip et créez une VM de génération 1 avec le VHDX comme disque.
  2. Démarrez la VM. Le disque s'agrandit tout seul à la taille du disque virtuel. L'écran de la VM affiche l'adresse de la console et le jeton de configuration.
  3. Ouvrez https://<adresse>:8443. Le navigateur avertit une fois au sujet du certificat auto-signé (remplacez-le plus tard dans Paramètres → Certificat). Saisissez le jeton et créez le premier administrateur.

L'appliance obtient son adresse par DHCP. Pour une adresse fixe, le nom du serveur ou le fuseau horaire, connectez-vous sur l'écran de la VM en tant que rzadmin (premier mot de passe rmmzit, à changer) : un menu de configuration s'ouvre. Le fuseau horaire et le réseau peuvent aussi être modifiés plus tard dans la console.

2. ISO de l'appliance

  1. Démarrez une VM ou un serveur sur rmmzit-appliance.iso. Après 5 secondes l'installation démarre seule : elle efface le premier disque, installe Debian, PostgreSQL et RMMZit et nécessite un accès Internet (10–20 minutes).
  2. Après le redémarrage, l'écran affiche l'adresse de la console et le jeton de configuration, comme avec l'image VM.

3. Script d'installation

Sur un serveur Linux existant, en root :

curl -fsSL https://github.com/Max-Zit/rmmzit/releases/latest/download/install.sh | sudo sh

Le script installe PostgreSQL, télécharge la dernière version, vérifie sa signature, crée une base de données avec un mot de passe aléatoire et démarre le service. Options (après sh -s --) : --version X, --db postgres://… pour une base existante, --no-auto-updates pour laisser désactivées les mises à jour de sécurité automatiques du système. Le relancer met RMMZit à jour en conservant les données.

4. Paquets à la main

sudo apt install ./rmmzit-server_X_amd64.deb      # Debian, Ubuntu
sudo dnf install ./rmmzit-server-X-1.x86_64.rpm     # AlmaLinux, Rocky Linux

Indiquez ensuite l'adresse de la base dans /etc/rmmzit/server.env (RMMZIT_DB=postgres://…) et démarrez le service avec systemctl enable --now rmmzit-server.

5. Docker

Le serveur existe aussi en image de conteneur, ghcr.io/max-zit/rmmzit, construite à partir du même paquet serveur signé que les autres méthodes ; il fonctionne avec PostgreSQL via Docker Compose. Téléchargez docker-compose.yml et .env.example dans un dossier, copiez .env.example en .env, définissez un mot de passe de base de données (lettres et chiffres) et le fuseau horaire, puis :

docker compose up -d
docker compose exec rmmzit rmmzit-server -setup-token

Ouvrez https://<hôte>:8443 et saisissez le jeton d'installation. Le port 8444 est le point d'accès des agents ; ouvrez-le là d'où les agents se connectent. Le tag de l'image dans .env décide de ce qui tourne : latest pour les versions officielles, testing pour les versions candidates.

Mettez à jour avec docker compose pull && docker compose up -d. Avant qu'une nouvelle version ne modifie la base de données, le serveur écrit une sauvegarde dans Paramètres → Sauvegarde de la console. Pour revenir en arrière, indiquez la version précédente comme tag de l'image et restaurez ce fichier : docker compose stop rmmzit, docker compose run --rm rmmzit -restore /var/lib/rmmzit/backups/FICHIER, docker compose up -d. Dans un conteneur, le réseau et le fuseau horaire relèvent de l'hôte Docker, pas de la console.

Première connexion

  • Le jeton de configuration se trouve dans /var/lib/rmmzit/setup-token.txt et dans le journal du serveur (journalctl -u rmmzit-server). Il ne sert qu'une fois.
  • Chaque compte nécessite une application d'authentification (TOTP) et reçoit 10 codes de récupération. Conservez-les en lieu sûr.
  • Par défaut la console n'accepte que les connexions des réseaux privés. Si vous vous bloquez, lancez rmmzit-server --reset-allowlist sur le serveur (appliance : menu de configuration, élément 5).

Où se trouvent les éléments

CheminContenu
/etc/rmmzit/server.envconfiguration : base de données, ports, source des mises à jour (lisible seulement par root et le service)
/var/lib/rmmzitrépertoire de données : certificats, clé secrète, installateurs des agents (downloads), journaux
/var/lib/rmmzit/logs/server.logjournal du serveur ; aussi dans journalctl -u rmmzit-server
/var/log/rmmzit-helperjournal de l'assistant root (mises à jour, fuseau horaire, réseau)

Sauvegardez la base de données avec /var/lib/rmmzit : la clé secrète qui s'y trouve déchiffre les mots de passe enregistrés et les certificats identifient le serveur auprès de ses agents.

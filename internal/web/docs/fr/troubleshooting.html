Dépannage et FAQ

Les questions les plus fréquentes et ce qu'il faut vérifier en premier. Pour une demande de support, téléchargez le diagnostic dans Paramètres → Diagnostic.

Je n'arrive pas à joindre la console

  • Votre adresse n'est peut-être pas dans les réseaux autorisés : la connexion est fermée avant TLS, le navigateur affiche donc une erreur de connexion. Lancez rmmzit-server --reset-allowlist sur le serveur (appliance : menu de configuration, élément 5) pour autoriser de nouveau tous les réseaux privés.
  • Après un changement de port, ouvrez la console sur le nouveau port.
  • Vérifiez le service sur le serveur : systemctl status rmmzit-server et journalctl -u rmmzit-server.

Problèmes de connexion

  • Le code est erroné — l'heure du téléphone doit être exacte (heure automatique).
  • Téléphone perdu — connectez-vous avec un code de récupération ; un autre administrateur peut réinitialiser la connexion à deux facteurs.
  • Trop d'échecs — l'adresse est bloquée un moment ; un administrateur peut la débloquer dans Paramètres → Connexion et sécurité. Les connexions depuis le serveur lui-même ne sont jamais bloquées.
  • LDAP / authentification unique — utilisez Tester sur la page LDAP ; vérifiez les groupes envoyés par le fournisseur. Le journal du serveur contient les détails.

Un agent ne se connecte pas

  • L'ordinateur peut-il joindre le port des agents ? Sous Windows : Test-NetConnection rmm.example.com -Port 8444.
  • L'adresse publique des agents est-elle correcte ? Les codes créés alors que la console était ouverte sur localhost envoient l'agent vers le mauvais serveur ; définissez l'adresse et créez un nouveau code.
  • Le code est-il encore valable et non épuisé ?
  • Journaux de l'agent : Windows C:\ProgramData\RMMZit Agent\agent.log, Linux /var/lib/rmmzit-agent/agent.log et journalctl -u rmmzit-agent ; pour un appareil connecté, ouvrez-les depuis la console dans Fichiers. Sous Windows, l'icône près de l'horloge montre l'état de la connexion.

Le bureau à distance n'affiche rien

  • Linux avec Wayland ne peut pas être affiché : connectez-vous avec une session X11 (Xorg) ou utilisez le terminal.
  • Linux sans bureau : utilisez le terminal.
  • Copier des fichiers par le presse-papiers nécessite un utilisateur connecté sur l'ordinateur Windows.

Les mises à jour Windows ne s'installent pas

  • Vérifiez l'installation automatique dans l'onglet Stratégie de l'appareil : quelle stratégie définit Windows Update, les jours, l'heure et le mode. Les appareils doivent être en ligne pendant cette heure.
  • L'onglet Mises à jour de l'appareil affiche la dernière recherche et son erreur, s'il y en a une.

Les e-mails d'alerte n'arrivent pas

Utilisez Envoyer un e-mail de test dans Paramètres → Surveillance et alertes ; le message affiche la réponse du serveur. Un mot de passe n'est envoyé que via STARTTLS ou TLS.

FAQ

RMMZit a-t-il besoin d'un service cloud ?

Non. Tout tourne sur votre serveur ; rien n'est envoyé à MaxZit. Le serveur vérifie seulement GitHub pour les nouvelles versions.

Comment sauvegarder RMMZit ?

Dans Paramètres → Sauvegarde de la console, le serveur sauvegarde chaque jour sa base de données, sa clé secrète et ses certificats, chiffrés si vous le souhaitez et copiés sur un serveur SFTP. Gardez une copie hors du serveur : sans la clé secrète, les mots de passe enregistrés ne peuvent pas être déchiffrés et les agents ne feraient pas confiance à un nouveau serveur.

Puis-je déplacer le serveur sur une nouvelle machine ?

Oui : installez RMMZit sur la nouvelle machine et restaurez-y une sauvegarde de la console (rmmzit-server -restore FICHIER, sur l'appliance l'élément 7 du menu de configuration). Gardez la même adresse, ou modifiez l'adresse publique des agents et faites pointer l'ancien nom vers la nouvelle machine ; les agents continuent de fonctionner car la sauvegarde contient les certificats du serveur.

Existe-t-il un agent macOS ?

Pas encore. Windows et Linux (x86-64, ARM64) sont pris en charge.

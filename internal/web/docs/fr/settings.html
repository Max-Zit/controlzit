Paramètres et mises à jour du serveur

Les administrateurs trouvent les paramètres du serveur dans Paramètres : réseau et ports, certificat, fuseau horaire, mises à jour du serveur et des agents, et diagnostic pour le support.

Réseau et accès

Dans Paramètres → Réseau et accès :

  • Console — adresse et port d'écoute (par défaut :8443) et les réseaux autorisés : une adresse IP ou un réseau par ligne (CIDR). Les connexions d'autres adresses sont fermées avant TLS ; le serveur lui-même (127.0.0.1) est toujours autorisé. L'enregistrement refuse une liste qui bloquerait votre propre adresse.
  • Point d'accès des agents — adresse et port d'écoute (par défaut :8444, différent de la console), les réseaux d'où les agents peuvent venir (vide = tous) et l'adresse publique des agents inscrite dans les installateurs et les codes d'inscription.
  • Les nouveaux ports s'appliquent après Redémarrer maintenant (redémarre le service RMMZit ; les agents se reconnectent d'eux-mêmes).

Si vous vous bloquez, lancez rmmzit-server --reset-allowlist sur le serveur (appliance : menu de configuration, élément 5).

Réseau du serveur (appliance)

Sur l'appliance RMMZit, le réseau du serveur lui-même se règle aussi ici : DHCP ou adresse fixe avec taille du réseau (p. ex. 192.168.1.20/24), passerelle, un à trois serveurs DNS et nom du serveur. Si la passerelle ne répond pas avec les nouveaux paramètres, les précédents reviennent d'eux-mêmes après 30 secondes. Sur les autres installations, c'est le système d'exploitation qui gère le réseau.

Fuseau horaire

Les planifications (mises à jour, scripts, rapports) et les heures de la console utilisent le fuseau horaire du serveur. Choisissez-le dans la liste et cliquez sur Définir ; la console redémarre et revient en quelques secondes. Sans l'assistant root (voir ci-dessous), réglez-le sur le serveur : timedatectl set-timezone Europe/Paris.

Certificat (HTTPS)

Dans Paramètres → Certificat, choisissez le certificat que voient les navigateurs en ouvrant la console. Les agents utilisent leur propre port et leur propre certificat : le modifier ne les déconnecte jamais.

  • Le certificat propre de la console (auto-signé) — fonctionne immédiatement ; les navigateurs avertissent.
  • Let's Encrypt — un certificat gratuit, renouvelé automatiquement 30 jours avant son expiration. Saisissez le nom DNS public de la console et une adresse e-mail, et choisissez la vérification :
    • port 80 — le nom pointe vers ce serveur et le port 80 est joignable depuis Internet ; le serveur répond sur le port 80 et redirige les navigateurs vers HTTPS ;
    • DNS Cloudflare — pour les serveurs non joignables depuis Internet ; nécessite un jeton d'API Cloudflare avec Zone:DNS:Edit pour la zone.
  • Téléverser un certificat de votre autorité de certification ou de l'AC de l'entreprise : le certificat (PEM, avec les certificats intermédiaires) et la clé privée. La clé n'est stockée que sur ce serveur.

Mises à jour du serveur

Paramètres → Mises à jour de RMMZit affiche la version en cours et la dernière version publiée. Installer met le serveur à jour : seules les versions signées avec la clé de publication RMMZit sont installées ; avant l'installation, le serveur sauvegarde sa base de données et son programme, et si la nouvelle version ne démarre pas, il revient de lui-même à l'ancienne. La console est indisponible une ou deux minutes. En option, les nouvelles versions s'installent automatiquement à une heure choisie.

Canal de mise à jour : Versions officielles (par défaut) ou Test, qui propose les versions candidates avant qu'elles deviennent officielles, pour une console de test. Gardez les consoles de production sur les versions officielles.

Les mises à jour, le fuseau horaire et le réseau nécessitent l'assistant root fourni avec les paquets Linux et l'appliance. Sans lui (p. ex. le programme seul), mettez à jour avec install.sh ou le paquet de la version.

Mises à jour des agents

Voir Installer les agents → Mises à jour des agents.

Diagnostic

Paramètres → Diagnostic montre où RMMZit écrit ses journaux, les dernières lignes du journal du serveur (filtre par niveau ou texte), le journal de l'assistant root et les versions. Télécharger le diagnostic (ZIP) crée un fichier pour le support avec les journaux, les versions et un résumé des paramètres, les appareils, les alertes et le journal d'audit. Les mots de passe, jetons, codes d'inscription et clés sont retirés de tout ce qui est affiché et du fichier ; les scripts et leur sortie ne sont pas inclus.

Champs personnalisés

Sous Paramètres → Champs personnalisés, les administrateurs ajoutent leurs propres champs pour les appareils et les clients — texte, nombre ou date —, par exemple un numéro d'inventaire, la fin de garantie ou un contrat. Les techniciens les remplissent sur les pages des appareils et des clients ; l'API renvoie les champs avec chaque appareil et les définit avec PUT /api/v1/devices/{id}/fields.

Sauvegarde de la console

Paramètres → Sauvegarde de la console sauvegarde la console chaque jour à l'heure choisie, ou immédiatement avec Sauvegarder maintenant. Une sauvegarde contient la base de données, la clé secrète des mots de passe enregistrés, les certificats et clés auxquels les agents font confiance, et la bibliothèque de logiciels. Les sauvegardes les plus récentes (autant que vous le choisissez) restent dans le dossier backups du répertoire de données et se téléchargent depuis la page.

Avec une phrase secrète, les fichiers sont chiffrés (AES-256-GCM) ; conservez-la ailleurs, car sans elle une sauvegarde ne peut pas être restaurée. Une copie de chaque sauvegarde peut aller dans un dossier SFTP sur un autre serveur (mot de passe ou clé privée). Le premier test de la connexion affiche la clé d'hôte du serveur à approuver ; les copies ne vont qu'à un serveur ayant cette clé. Si une sauvegarde ou sa copie échoue, les destinataires des e-mails d'alerte reçoivent un e-mail.

Une restauration s'exécute serveur arrêté : sur l'appliance dans le menu de configuration (Restore a backup), avec les paquets Linux :

sudo systemctl stop rmmzit-server
sudo -u rmmzit sh -c 'set -a; . /etc/rmmzit/server.env; rmmzit-server -data-dir /var/lib/rmmzit -restore /path/rmmzit-backup-….czb'
sudo systemctl start rmmzit-server

La phrase secrète d'une sauvegarde chiffrée est lue dans RMMZIT_BACKUP_PASSPHRASE ou dans un fichier indiqué par -restore-passphrase-file. La base de données est restaurée en une seule étape (rien ne change en cas d'échec) ; une version plus récente de RMMZit met à jour la base restaurée au démarrage. Un nouveau serveur restauré depuis une sauvegarde garde tous les agents, car ils font confiance au même certificat.

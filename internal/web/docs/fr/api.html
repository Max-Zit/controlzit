API

L'API REST permet aux scripts et autres outils de lire les appareils, alertes et tâches et de lancer du travail sur les appareils, avec les mêmes droits que dans la console.

Jetons

Créez un jeton dans Mon compte → Jetons d'API : un nom, un rôle qui ne dépasse pas le vôtre (lecture seule, technicien ou administrateur) et sa durée de validité. Le jeton n'est affiché qu'une fois ; conservez-le comme un mot de passe. Il agit en votre nom, avec vos clients. Envoyez-le dans chaque requête sous la forme Authorization: Bearer czt_… à l'adresse de la console (port 8443), qui n'accepte que les connexions des réseaux autorisés. Les cookies de session du navigateur ne fonctionnent pas sur l'API. Supprimer le jeton sur la page du compte met fin à son accès immédiatement.

Tâches

Une tâche attend que l'appareil soit en ligne et s'exécute après les tâches précédentes de l'appareil, comme les actions de la console ; elle apparaît dans l'Activité de l'appareil. La réponse est 202 avec la tâche ; suivez-la avec GET /api/v1/tasks/{id} jusqu'à ce que son statut soit done, failed, cancelled ou expired. Les types et leurs champs :

{"kind": "script", "shell": "powershell", "script": "Get-Service Spooler", "timeout": 120}
{"kind": "patch.scan"}
{"kind": "patch.install", "updates": [], "reboot": false}
{"kind": "winget", "action": "install", "id": "7zip.7zip"}
{"kind": "choco", "action": "upgrade", "id": "firefox"}
{"kind": "power", "action": "restart", "delay": 300, "message": "Restart for updates"}
{"kind": "agent.update"}
{"kind": "bitlocker.keys"}

Exemples

Un script PowerShell sur l'appareil 9, puis son résultat :

curl -s -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"kind":"script","shell":"powershell","script":"Get-Date","timeout":60}' \
  https://rmm.example.com:8443/api/v1/devices/9/tasks
curl -s -H "Authorization: Bearer $TOKEN" https://rmm.example.com:8443/api/v1/tasks/42

$h = @{ Authorization = "Bearer $env:CZ_TOKEN" }
Invoke-RestMethod -Headers $h https://rmm.example.com:8443/api/v1/alerts

Erreurs

Les erreurs arrivent en JSON {"error": "…"} avec le statut HTTP : 400 pour une requête invalide, 401 pour un jeton absent, faux ou expiré, 403 quand le rôle du jeton n'autorise pas l'appel, 404 pour quelque chose qui n'existe pas ou que le jeton ne peut pas voir, 409 quand une tâche est déjà terminée, 429 après trop de connexions échouées depuis l'adresse. Chaque modification via l'API est consignée dans le journal d'activité avec le nom du jeton.
